# 第一次调用的三个定性模块：撰写者 + 审核者（子项目四）

> 2026-10-17。子项目二（方法论预研）、子项目三（判断项）已把「内容由谁判」从代码
> 换成了 AI 审核者。本文把同一套做法延伸到第一次调用 `--analyse` 的三个定性模块：
> 宏观定性（`macro_view`）、战略分析（`strategy`）、产业链（`value_chain`）。

## 背景

中国巨石（600176，2025）第一次调用：战略分析的五力连续 3 次被代码判「缺少可核验的
依据（需年报原文或占位符）」—— 模型引的是研报 —— 战略分析整节缺失，后面的辩论与
简报少了护城河、五力一块。

三个模块是同一套写法、同一类代码闸门（重试 3 次，仍不过整节缺失）：

| 模块 | 代码闸门 |
|---|---|
| 宏观定性 | 政策取向/传导影响只能填规定的词；必须给政策取向、传导至少 2 条；描述里不能有账本外数字；依据必须是原文引号或占位符，且逐字找得到 |
| 战略分析 | 护城河类型、五力名称、强弱等级只能填规定的词；护城河 ≥1、五力 5 条齐全、关键不确定性 ≥2；账本外数字；依据必须是年报原文或占位符，且逐字找得到 |
| 产业链 | 环节位置只能是上游/本环节/下游，议价强弱只能填规定的词；三个环节都要有、对上游与下游的议价都要给；账本外数字；依据逐字核验 |

判断项环节当初正是「依据必须逐字」这道闸门拦下约一半产出，后来放宽；生益科技、
贵州茅台两次成稿辩论都抓到「把应付账款周转天数短解读成议价强势」—— 这类与账本数据
相矛盾的判断，代码闸门一条也拦不住。

## 用户决定（2026-10-17）

1. 宏观定性、战略分析、产业链**都改由审核者审核**。
2. **沿用各模块的方法论**（分析框架、输出格式、可选词都不动），修改的是审核标准。
3. **取消「依据必须逐字出自原文」**：依据可以是账本占位符、原文引用（年报、公告、
   研报、外部文档都可），或转述/综合（写明采纳了哪几篇文章的观点，由人复核）。
4. 流程照搬判断项环节：四级结论（通过 / 提醒 / 致命 / 待采集，定义原话同子项目二）、
   致命必附「建议：…」、可附选填的「补充」、最多 3 轮。
5. 清单**按方法论生成，不按稿子生成**（五力永远 5 条，漏写的审核者看到「未给出」）。
6. 审核者的资料：撰写者看到的全部 + 代码事实（引文核验结果、转述指向的文章是否在语料
   库里）+ 完整账本事实目录（`FactCatalog`），**不联网**。来源分级（如财经媒体「仅作
   线索」）由审核者判断。
7. 描述里出现账本外数字：**改为交审核者的事实，不再驳回**（研报撰写环节的占位符契约
   仍是交付底线）。
8. 三个模块各自独立审核、各自三轮，互不影响。
9. **任一模块 3 轮未通过（或审核者答不全、模型接口失败）→ 整个第一次调用停下交人工**：
   三个模块照常都跑完再停；不出资料来源清单、不进门①；终端写明哪个模块没过、各轮
   记录在哪；接口失败写明是接口问题、重跑即可。
10. 每个模块各自落盘：各轮记录（撰写者原文、代码事实、审核者每次作答）；通过的存审核
    结论与指纹；没通过的存最后一稿。
11. **重跑时通过的模块直接沿用，只重做没通过的**。
12. 人工接手：以最后一稿为底稿改好、存成该模块的结果文件，重跑 `--analyse`；读回时
    标注「人工修改后未经审核」，带进门① 清单与研报。

## 一、流程（每个模块各自一遍）

1. **撰写者**按现有提示词写（方法论、格式、可选词不动；提示词里「依据必须逐字」「会被
   驳回」类说法改写为新的依据写法与「由审核者逐项审核」）。
2. **代码只读**：按现有格式逐行读，读不出的行（段数不够、可选词认不出、占位符格式不合法）
   跳过并记成事实；不判条数、不判可选词以外的内容、不驳回。
3. **代码核对，记成事实**：引文能否在资料里找到（年报摘录、语料库、账本）；转述指明的
   文章是否在语料库里；描述里有没有账本外数字。
4. **审核者**按清单逐条作答，可附「补充」。漏答退回补答，最多 2 次，不消耗撰写者轮数。
5. 有致命 → 致命项（含理由与建议）与提醒项交回撰写者重写，算一轮；最多 3 轮。

**模型接口失败**：撰写者或审核者任一次调用的接口失败（额度、超时、CLI 报错）都算该模块
没通过，同样触发停下；终端写明是接口问题、原样重跑 `--analyse` 即可。`_analyse_qualitative`
里 `take()` 对这三个模块不再把异常吞成「该节缺失」。（用户决定 9 的范围，讨论中已定。）

模块没有可用资料时（例如宏观定性没有外部宏观资料、战略与产业链既无年报摘录也无语料库）
照旧跳过并在终端说明 —— **那是数据缺失，不是审核没过，不触发停下**。（写设计时的判断：
用户决定 9 说的是审核没通过。）

## 二、依据的三种写法

| 写法 | 例 | 代码核对什么（结果只作事实） |
|---|---|---|
| 账本占位符 | `[[payable_days@2025FY]]` | 账本里有没有这条 |
| 原文引用 | `「…」——《年报》经营情况讨论` 或 `「…」——东莞证券《…》` | 引文能否在年报摘录或语料库里逐字找到 |
| 转述/综合 | `转述：综合 东莞证券《…》、国信证券《…》` | 列出的文章是否在语料库里 |

三种都合法；核验不过、文章找不到只作为事实交给审核者。现有 `attribute`（给依据补
出处）照旧调用。提示词里写清：能逐字引就逐字引，转述要写明出处文章。

## 三、审核清单（审核标准）

**宏观定性**

| 条目 | 判什么 |
|---|---|
| [取向] 政策取向 | 宽松/中性/收紧与证据是否一致；与账本利率、信用数据（如期限利差）是否矛盾 |
| [传导] 每条传导路径 | 链条每一环是否成立、是否真的传到本行业；利好/中性/利空与链条方向是否一致；依据是否支撑 |
| [遗漏] 一条 | 有没有漏掉对本行业最要紧的宏观因素 |

[传导] 条目按撰写者给出的路径逐条列；一条都没读进来时列一条「[传导] 传导路径」，
让审核者判「未给出」。

**战略分析**

| 条目 | 判什么 |
|---|---|
| [护城河] 每条（一条都没有时列一条「护城河」） | 类型与宽度是否有证据；「无明显护城河」也判是否成立 |
| [五力] 现有竞争强度、新进入者威胁、供应商议价能力、买方议价能力、替代品威胁（固定 5 条） | 高/中/低与「对本司有利/中性/不利」是否一致；依据是否支撑；**与账本数据是否矛盾**（应付/应收周转天数、毛利率分位等） |
| [不确定性] 每条（少于 2 条时补列「不确定性（未给出）」到 2 条） | 是否真是关键变量；映射的驱动因子对不对；「不利时如何变化」方向对不对 |
| [自洽] 一条 | 护城河、五力、不确定性三部分是否彼此矛盾 |

**产业链**

| 条目 | 判什么 |
|---|---|
| [环节] 上游、本环节、下游（固定 3 条） | 环节识别是否正确；对本公司意味着什么是否说清 |
| [议价] 对上游、对下游（固定 2 条） | 强/均衡/弱判断与证据、与账本周转天数是否一致 |
| [规模] 行业规模（撰写者给了才列） | 口径、数值、单位、期间是否对得上 |

**账本外数字**（写设计时的判断）：审核规则写明 —— 描述会原样进入后两次调用（辩论、简报、
研报撰写），那里的数字必须可溯源；每个账本外数字要看撰写者有没有指明出处：有出处判提醒
（建议改成不带数字的说法或换成占位符），没出处、又支撑了关键结论的判致命。代码照旧把
账本外数字列成事实，不在落盘前改写 summary。

作答格式、四级定义、致命必附建议、「补充」、条目名容错，全部沿用 `methodology_review`
的解析器（`parse(kinds=…)`，先精确后容错）。

## 四、审核者的资料

- 撰写者看到的全部：该模块现有的证据文本（`for_prompt` 等）。
- 代码事实：每条依据的核对结果；读不出的行；账本外数字。
- 完整账本事实目录（`FactCatalog.render_for_prompt()`）。
- 不联网。

## 五、停下、落盘、沿用与人工接手

**落盘**（每个模块一组，前缀 `macro_view` / `strategy` / `value_chain`）：

| 文件 | 内容 |
|---|---|
| `<模块>_rounds.md` | 每一轮：撰写者原文、代码事实、审核者每次作答原文与逐条结论 |
| `<模块>_review.json` | 通过时：逐条结论、第几轮通过、指纹（撰写者原文去掉空白后的哈希） |
| `<模块>.md` | 通过时：该模块的结果（撰写者原文，即可读回的格式行）；人工接手也写这个文件 |
| `<模块>_failed_raw.md` | 没通过时：最后一稿原文 |

**停下**：三个模块都跑完后，若有模块没通过 → 第一次调用 stage 为未完成，不写
`sources.md`、不进门①；终端逐个写明「宏观定性审核 3 轮未通过（最后一轮致命 N 条）—— 各轮
记录：…；最后一稿：…」；「下一步」给两条做法：原样重跑 `--analyse`；以最后一稿为底稿改好
存成 `<模块>.md` 再重跑（读回时标注「人工修改后未经审核」）。新措辞登记进 `research._PREFIX`。

**沿用**：重跑 `--analyse` 时，`<模块>.md` 存在 → 读回，不调模型：
- 指纹与 `<模块>_review.json` 一致 → 沿用审核结论；
- 不一致或没有审核记录 → 标注「人工修改后未经审核」（终端、门① 清单、研报附录）。

**沿用时资料可能已经变了**（写设计时的判断）：重跑 `--analyse` 会重新联网采集，语料库可能
与审核时不同。沿用的模块**不重审**，但代码对它重做一遍依据核对；引用或转述的文章若本轮
语料库里已不在，在终端与门① 清单里标注「本模块引用的 N 篇文章本轮已不在语料库」，供人
判断。审核时的语料库指纹（文档 id 集合的哈希）写进 `<模块>_review.json`，便于事后对照。

读回后要重建下游依赖：产业链的行业规模照旧写进账本；战略的结果照旧挂到 `r.strategy_view`。

## 六、下游

- 三个模块的结论照旧以 `view.summary()` 进 `state.json` 的 `md`，供后两次调用读回；
  审核的提醒、待采集附在各自 summary 末尾（「审核遗留」），让辩论、简报看得到。
- 门① `sources.md` 新增「定性分析审核」一节：每个模块第几轮通过、提醒与待采集；人工
  修改过的写明未经审核。
- **研报里的落点**（写设计时的判断）：沿用判断项的做法 —— 第一次调用把「人工修改后未经
  审核」的模块名记进 `state.json`；第二阶段 `--value` 把它们加进研报末尾已有的「⚠ 判断项
  依据核验」附录（附录在 `audit()` 之后由代码追加），进提示词的那句不带数字；终端走
  `skipped` 并登记 `research._PREFIX`。summary 末尾的「审核遗留」照旧带进辩论与简报的上下文。

## 七、测试（不调模型）

- 读数：读不出的行跳过并记事实；可选词以外的写法、条数不够都不驳回。
- 依据：三种写法都读得进；核验不过、文章不在语料库只作事实。
- 清单：按方法论生成（五力固定 5 条、产业链 3+2 条、宏观传导按路径条数）；漏写的出现在清单里。
- 审核循环：沿用子项目三的测试套路（致命退回带建议、补答不耗轮数、3 轮停下、答不全停下）。
- 停下：一个模块没通过 → 其余模块照常跑完、第一次调用未完成、不写 `sources.md`、终端两条做法。
- 沿用：通过的模块重跑不调模型；人改过的标注未经审核。
- 回放：中国巨石这次的失败（五力引研报）不再被代码拒绝，成为审核者的事实。
- 端到端：第一次调用三个模块都通过 → 门①；一个模块 3 轮不过 → 停在第一次调用。
- 关键规则做变异验证。

## 不做

- 不改三个模块的方法论（框架、格式、可选词）。
- 不改研报撰写的占位符契约、成稿辩论、辩论后回写。
- 不改多空辩论（`stance`）。
- 审核者不联网。

## 留给实现者

- `methodology_review` / `assume_review` 里可复用的部分（作答解析、各轮记录渲染、指纹、
  `ReviewStop`）抽成共用代码还是各模块引用，由实现者定。
- 三个模块的审核规则提示词措辞。
