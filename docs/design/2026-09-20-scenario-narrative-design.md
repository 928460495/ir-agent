# 情景叙事设计（Plan 2B）

> 缘起：plan-0 路线图的 Plan 2B 行只有一句「每档叙事；变量方向一致性校验」，
> 没有规格。本文把它变成可实施的设计。

## 一、范围收敛：方向约束已经完成

路线图把「每档叙事」与「变量方向一致性校验」写在一起，但后者**已由现有的
`_check_monotonic` 完成**，且是致命级校验。

需要说清它查的是什么：**合成结果跨档单调**（`lo[i] < mid[i] < hi[i]`），
而不是逐因子跨档单调。这是有意为之——因子的「坏方向」取决于它是收益项还是
成本项：「产能变化率」悲观档数值更小，「上游成本变化率」悲观档数值更**大**，
代码无从知道一个因子属于哪一种，逐因子比大小没有良定义。

用户决定**保持现状**，不加跨因子同向性校验。理由与本项目原则一致：跨因子
同向要 AI 自我声明，而声明本身不可被代码验证，引入一个只能靠模型自觉的闸门
与「只信可核验的东西」相冲突。

**因此 Plan 2B 只做「每档叙事」。**

## 二、要解决的问题

叙事按「因子 × 年份」组织（9 因子 × 5 年 = 45 个格子各一句），而情景按「档」
组织。两者正交。

于是 Bear 档的完整故事被打散在 45 个分句里，**没有任何地方能读到「悲观情景
到底讲的是什么」**。人在批准时看到的是一堆局部解释，拼不出一个世界。

实例（600183 实跑）：

```
| 2026E | 5.00% | 10.00% | 15.00% | 理由：年报披露公司拥有全球第二大产能，
中性档取扩产初期的中等增速；悲观档对应风险提示中 AI 资本开支不及预期时公司
主动放缓资本开支节奏；乐观档对应 AI 驱动的持续扩产 |
```

三档的解释挤在一个字段里用分号隔开，而这只是 45 格中的一格。

## 三、架构

叙事按档组织，与按「因子 × 年份」组织的 `Row` 正交，因此**不塞进 `Row`**，
新增独立结构挂在 `AssumptionSet` 上：

```python
@dataclass(frozen=True)
class Narrative:
    """一档情景的叙事。**按档组织，与按「因子×年份」组织的 Row 正交。**"""
    case: Case                    # BULL / BASE / BEAR
    story: str                    # 这一档假设的世界长什么样
    drivers: list[str]            # AI 自述本档下发力的因子（不校验，见第五节）
```

`AssumptionSet` 新增 `narratives: dict[Case, Narrative]`，与 `decomps` /
`factor_data` / `residuals` 同级——都是派生/附加信息，不影响合成。

数据流：

```
_factor_head 提示词（要求先叙事后因子）
      ↓
模型一次输出：3 段叙事 + 45 行因子
      ↓
_parse_narratives（扫 `情景:` 行）   _parse_factors（扫 `假设:` 行）
      ↓                                    ↓
   narratives                            rows
      ↓                                    ↓
            describe() 渲染：叙事在顶、因子表在下
```

**两个解析器彼此独立**：叙事解析失败不影响因子行，反之亦然。

### 一条硬性设计约束

**叙事不参与任何校验，也不影响合成。** 它是纯展示层的附加信息。

叙事写崩的最坏后果是「批准清单上少了三段话」，而不是「整轮判断项作废」。
本项目吃过相反的亏——一个专为「留痕可信」写的任务，留痕却成了阻断路径的
一部分。**给人看的东西不该有能力拦住给模型算的东西。**

## 四、提示词契约与解析

模型在同一次输出里**先写三段叙事，再填因子行**（叙事前置）。

选择前置而非后置的理由：格式漂移通常发生在长输出的尾部（实跑记录：模型写到
45 行后改用散文式粗体条目）。前置让叙事躲开最危险的区段；且「先定故事再填数」
符合人的思维顺序。更重要的是**失败互不牵连**——叙事在前，因子行失败时叙事
仍可用；叙事失败时因子行还没被污染。

两类行用不同前缀区分：

```
情景: 悲观 | <这一档假设的世界> | <发力因子，顿号分隔>
情景: 中性 | … | …
情景: 乐观 | … | …

假设: 产能 | 第1年 | 5% | 10% | 15% | 依据：…
（余下 44 行）
```

- `情景:` 用 `lineparse.keyed("情景")` 解析，与 `假设:` 同一套机制，**不新造语法**
- 档位名用「悲观/中性/乐观」，与 `Case` 枚举的 `value` 一致
  （`BULL="乐观"` / `BASE="中性"` / `BEAR="悲观"`），不引入第二套叫法

### 解析规则

- 三档**必须齐全**，缺任何一档 → 整个叙事块作废（`narratives` 为空），
  因子行照常生效
- 叙事正文**不带阿拉伯数字**——它会进研报提示词，而研报正文每个数字必须是
  占位符，照抄会被裸数字审计判掉（本项目已踩过多次）。期限写中文数字
- 发力因子必须是本次分解式里真实存在的因子标签，否则该档 `drivers` 置空
  并在清单上标注「AI 给出的因子名不在分解式内，已忽略」

最后一条**不是**在校验归因对不对，而是在校验**它指的东西存不存在**。这正是
本项目反复出现的那条线：「这句话我确实抓到过」可核验，「这句话是对的」不可
核验。因子名在不在分解式里属于前者——查不过就是模型编了个不存在的因子名，
那不是判断分歧，是凭空捏造。

### 失败处置

叙事块解析失败**不重试、不驳回**，只在清单顶部标注「本轮未产出情景叙事」。
因子模式已有 3 次重试额度，不该被叙事占用。

## 五、呈现：叙事与归因并列

`describe()` 在批准清单顶部、锚定横幅之后、因子表之前插入：

```markdown
## 情景叙事

### 悲观
<AI 写的这一档世界>

AI 自述发力因子：稼动率、覆铜板ASP
代码实测贡献（对合成结果）：稼动率 −3.2pp、ASP −2.1pp、产能 +1.4pp、汇率 −0.3pp
```

两行并列，**不比对、不驳回**。读者若发现 AI 说的和数字对不上，自己看得出来。

### 归因由谁给出

用户决定：**AI 写，不校验**。

本设计的记录性异议：本项目有具体的失效先例——8 个因子的理由白纸黑字写着
「无数据（估计）」，依据列却挂着一个真实存在、方向上沾边的占位符，于是底部
「没有证据支撑」的名单从 8 个缩到 1 个。当时的判据是「按理由自述归类」，
修复方式正是改成「按有没有挂依据判」。归因是同一类东西：一句不可核验的自述，
摆在数字旁边，读起来像是从数字推出来的。

折中处置：**把代码算出的贡献值一并印在归因旁边**，不驳回、不比对，只是并列
摆着。这既不引入会失败的闸门，也不让不可核验的声明独占版面。

### 贡献值算法

- **营收（乘法链）**：把该因子换成 0（无变化）重算合成，与原合成的差 = 该因子贡献
- **毛利率（加法链）**：该因子的 pp 值就是贡献，直接读

按绝对值从大到小排，取全部因子（分解式每链最多 5 个，不会太长）。

这行数字本身就是新增的分析信息：它回答「这一档的增速差异到底是谁造成的」，
而这在 45 行因子表里根本看不出来——人要自己把 Π(1+r) 在脑子里算一遍才知道。
即便完全不管 AI 的自述，它也值得印。AI 的自述放在旁边，读者获得的是两个独立
视角：模型的理解，与数学事实。

### 研报侧

叙事随 `assumptions.json` 跨阶段存活，进完整研报的情景一节。
归因数字在研报里**不重印**——研报正文每个数字必须是占位符，而这些贡献值不在
账本里，印了会被裸数字审计判掉。研报只用叙事文字。

## 六、跨阶段存活

`narratives` 进 `to_json` / `from_json`，与 `decomps` / `factor_key` 同路。
人工在两阶段之间批准，第二阶段是新进程——不存就丢了（本项目为这个坑修过一次：
依据没跨阶段存活，第二阶段被自己的闸门拒掉）。

`drivers` 一并存；贡献值**不存**，第二阶段重算。

**能重算的就不要存。** 本项目的经验是同一个数有两个来源早晚会分叉——Plan 1
为此把锚定规则收进 `anchor_three` 只留一份，Plan 2A 终审又抓到 `share3` 被
算两次。贡献值是纯函数（因子值 → 贡献），重算成本为零，而存一份副本就多了
一条「存的时候是对的、读回来时代码已经改了」的路径。

## 七、错误处理（全部不阻断）

| 情形 | 处置 |
|---|---|
| 三档不齐 | 整块作废，清单标注「本轮未产出情景叙事」 |
| 叙事含阿拉伯数字 | 该档作废并标注原因 |
| 因子名不在分解式内 | 该档 `drivers` 置空并标注「已忽略」 |
| 两标量降级模式 | 不产出叙事（没有因子可归因），不报错 |

## 八、测试

- 三档齐全 → 解析出 3 条，`case` 与枚举对得上
- 缺一档 → 整块作废，**而因子行照常生效**（失败不牵连，是方案 A 的核心承诺）
- 叙事带阿拉伯数字 → 该档作废并标注
- 编造的因子名 → `drivers` 置空并标注
- 贡献值算法：乘法链用已知因子值手算验证；加法链直接比对 pp
- 跨阶段：`to_json → from_json` 后叙事逐字还原
- **降级路径不产出叙事且不报错**

## 九、不做什么

- 不做跨因子同向性校验（第一节已论证）
- 不做因果链校验（因果声明本身不可被代码验证）
- 不校验 AI 的归因是否与数字相符（用户决定；代码贡献值并列印出作为补偿）
- 不让叙事参与任何阻断路径
