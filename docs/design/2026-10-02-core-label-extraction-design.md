# 因子标签的关键词提取（B3）

## 一、这件事是实跑逼出来的，不是推演出来的

子项目 B 的 Task 8 实跑（`out/600183-subB`，2026-10-01，开销 $11.61）里，
8 个因子**全部**落「无数据」，②年报章节、②.5 公司公告、③研报语料库三级
文本命中**全为 0**。

公告那一半是成功的：135 条候选、模型挑 8 条（顶 `MAX_ANNOUNCEMENTS`）、
取文 0 失败、入库正文合计 89055 字，挑中的包括年报、半年报、三季报与一篇
《关于投资建设高性能覆铜板项目的公告》。材料在，命中是 0。

原因查清了，而且不是「A 股不披露」：

本轮的因子标签由模型逐轮生成，形状是这种：

    覆铜板下游需求规模(服务器/通信/消费电子PCB用量)
    产品结构升级(高端CCL如M6/M7/AI服务器用板占比提升)
    原材料成本(铜箔/电子级玻纤布/环氧树脂价格)

而 `_core_label` **只剥 `_SUFFIXES` 里的后缀**（`变化率`/`贡献`/`增速`…）。
这些标签不以任何后缀结尾，于是**原样返回**——三个匹配器拿着整串
`覆铜板下游需求规模(服务器/通信/消费电子PCB用量)` 去 89055 字正文里找，
0 次命中，必然。

对照：ow4 那轮模型给的是 `名义产能`/`产能利用率`/`ASP`/`良率` 这类短词，
③ 当时命中 1/8。**同一份代码、同一家公司、同一批数据源，只因为上游一个
环节的输出风格变了，下游三级证据供给从 1/8 掉到 0/8。** 这种脆性不报错、
不抛异常、单元测试全绿（测试用的是手写的短标签），只在真实跑起来、而且
恰好那一轮模型话多的时候静默归零。

## 二、实测排除了两条看似显然的做法

设计之前拿本轮真实语料（8 篇公告，89055 字）逐策略实测过。结论改变了方案：

| 策略 | 候选词 | 命中 | 判断 |
|---|---|---|---|
| 现状：整串标签 | 全部 7 个标签 | **0** | — |
| 去括号取头 | `原材料成本` | 2 | ✅ 真证据 |
| 去括号取头 | `覆铜板下游需求规模` / `产品结构升级` / `公司覆铜板市占率` / `覆铜板平均单价ASP` / `汇兑损益` | 0 | 确实不在 |
| 括号内切分 | `铜箔` | 6 | ✅ 真证据，但它是**成本的组成**不是成本 |
| 括号内切分 | `服务器` | **18** | ❌ 泛词，命中是巧合 |
| 括号内切分 | `通信` | 4 | ❌ 同上 |
| `source_hint` 里的引号术语 | `经营情况讨论与分析` | 1 | ❌ 那是**章节标题**，不是数据 |

**被排除的做法一：靠长度阈值区分。** `铜箔` 2 字是真信号、`通信` 2 字是
巧合——长度分不开。`_core_label` 现有的 docstring 里已经记着一条同形教训：
上一轮有人把阈值从 2 提到 4，想靠「核心词够长」挡住否定语境误判，实测防不住，
因为失败模式跟长度无关。**这次也一样：失败模式是泛化程度，不是长度。**

**被排除的做法二：下探括号内的词。** 它同时是最大的收益源（`铜箔` 6 次）
和最大的风险源（`服务器` 18 次）。决定是**不下探**，理由见第三节。

## 三、三个决定

### 范围：只改 `_core_label` 的提取

实跑顺带查出另外两件事，**都明确不在本 spec 范围内**：

- **`PDF_MAX_PAGES = 30` 套在 235 页的年报上。** 2025 年报 235 页、2026
  半年报 187 页，各只有 30 页进语料库（12.8% / 16%）。`汇兑损益` 实际出现在
  年报第 112、169、185 页——全在截断之外。但这只影响 ②.5，而 `annual_sections`
  **没有页数上限**（它对整本年报做关键词全文搜索），所以 ② 本来就完整读年报。
- **②.5 的槽位浪费。** 8 个公告槽位里 2 个花在年报与半年报上，而 ② 把这两份
  读得更好（不截断、按章节定位）。公告挑选或许该跳过年报/半年报，把槽位留给
  ② 拿不到的临时公告。

之所以先做提取：**它是三级文本命中的共同成因**，改一处三级同时受益，而
`annual_sections` 已经把整本年报摆在那里——提取一修好，② 立刻有最大的语料面
可用。

### 判据：按特指度排序，命中即停，不引入新过滤器

候选词按「越具体越优先」排序，第一个非否定命中就采用，不再往下试。
**不引入「窗口里必须有数字」这类新的过滤条件**——那会同时收紧 ② 与 ③，
可能把 ow4 那条唯一的研报命中也滤掉，是一笔没必要在本 spec 里做的交易。

### 阶梯在头停住，绝不下探括号内

括号里写的是**举例或注解**，不是因子的名字：

- `原材料成本(铜箔/电子级玻纤布/环氧树脂价格)` —— 括号内枚举的是成本的
  **组成项**。拿一个组成项的命中当成整个因子的证据，是归因错位。
- `覆铜板下游需求规模(服务器/通信/消费电子PCB用量)` —— 括号内是**下游行业名**。
  `服务器` 在一家覆铜板公司的公告里出现 18 次毫不意外，那不是「下游需求规模」
  的证据。

而**代价不对称**：一次巧合命中会把一条错摆的原文放在一个 DCF 因子后面，并被
标成「年报披露」/「公告披露」；一次漏判只是退到 ④ 或「无数据」。`gaps` 自己的
注释写着这正是本模块要防的最严重失败模式——「把一个巧合伪装成证据」。

**本轮落地后的实际效果，逐条算清：**

| 标签 | 候选词数 | 新增候选 | 在公告语料里命中 |
|---|---|---|---|
| `原材料成本(铜箔/…)` | 2 | `原材料成本` | **2 次 ✅** |
| `覆铜板下游需求规模(服务器/…)` | 2 | `覆铜板下游需求规模` | 0 |
| `产能利用率(稼动率同比变化)` | 2 | `产能利用率` | 0 |
| `产品结构升级(高端CCL如…)` | 2 | `产品结构升级` | 0 |
| `汇兑损益(出口业务…)` | 2 | `汇兑损益` | 0 |
| `公司覆铜板市占率` | **1** | **无**（无括号无后缀） | 0 |
| `覆铜板平均单价ASP` | **1** | **无**（同上） | 0 |

**即 7 个标签里 5 个多拿到一个候选词，其中 1 个真命中；另 2 个 B3 完全
不改变其行为。** 对公告语料是 0/8 → 1/8。

这就是老实的结果，不粉饰。②的语料面大得多（`annual_sections` 读整本
235 页年报，不截断），所以 ② 的收益应当高于这张表——但**本轮产物不持久化
`sections`，无从测量**，要等下一次实跑才知道。不要把「② 应当更好」当成
已经验证过的事。

## 四、设计

### `_core_label` 一行不动

它保持单一职责（剥 `_SUFFIXES` 后缀），`tests/test_gaps.py:392-399` 那 7 条
断言原样继续守它——它们编码的是本仓库自己的规范因子名
（`有效产能变化率`→`有效产能`、`先进封装收入占比提升贡献`→`先进封装收入`…）。

### 新增 `_core_candidates(label) -> list[str]`

```python
_PAREN = re.compile(r"[（(][^）)]*[）)]")


def _core_candidates(label: str) -> list[str]:
    """按特指度降序的候选词，调用方命中即停。**绝不下探括号内。**"""
    out: list[str] = []

    def add(c: str) -> None:
        if len(c) >= 2 and c not in out:
            out.append(c)

    add(label)                              # L1 整串标签
    head = _PAREN.sub("", label).strip()    # L2 去掉括号及其内容
    add(head)
    add(_core_label(head))                  # L3 头再剥后缀
    return out
```

- **2 字下限保留**，连同它既有的理由：一两个字的片段几乎到处都能命中。
- **括号不闭合时**（`产能(稼动率`）正则不匹配，`head` 等于整串——退化方向
  保守，落空退 ④。
- 无括号的标签（`有效产能变化率`）得到 `[有效产能变化率, 有效产能]`：比现状
  多试一次整串。整串若真的逐字出现，那是更强的命中；不出现就落到现状那一级。

### 三个匹配器：候选外层，容器内层

`_match_annual`（`gaps.py:208`）、`_match_report`（`:242`）、
`_match_announce`（`:263`）三处把

```python
core = _core_label(label)
```

换成遍历 `_core_candidates(label)`，**候选词在外层循环、章节/文档在内层**：

```python
for core in _core_candidates(label):
    for s in sections.sections.values():
        hit = _valid_hit(s.text, core)
        if hit is not None:
            return hit, name
```

**顺序不能反。** 若容器在外层，一个较泛的候选词在靠前的章节里命中，会压过一个
更具体的候选词在靠后的章节里的命中——那等于悄悄放弃了「按特指度排序」这整个
决定。

### `_valid_hit` 一行不动

否定语境的判断逐候选词生效。现有四条否定测试
（`test_未披露被短核心词误判为年报披露`、`test_否定语境不因核心词够长而免疫`、
`test_否定语境之外的真实命中不受连坐`、`test_公告的否定语境不算命中`）
是回归保护，必须继续绿。

## 五、两条代价，明确记下来

**① 「待人工确认」的面会扩大。** `年报披露`/`公告披露`/`研报测算` 三个状态的
含义都是「文字依据，是否给出具体数值待人工确认」。命中变多等于人要核的条目
变多。这是预期的交易，不是免费的。

**② 它把子项目 B 终审 Important #1 的地盘变大了。** `assume.py:952` 的闸门
对任何非 `MISSING` 状态硬驳回「无数据（估计）」。B3 让更多因子拿到非 MISSING
状态，而摘录里可能**仍然没有数值**——那时模型唯一诚实的答案正好是被驳回的
那个。子项目 B 已经把 `公告披露` 补进了提示词的状态枚举（commit `f29005a`），
闸门与提示词现在一致；但 B3 让这个张力出现得更频繁。若实跑中观察到因此反复
被驳回，该动的是闸门或那条出口，不是回头把提取改窄。

## 六、测试

**反向断言是这一节的核心**，它钉的是第三节那个决定：

```python
def test_候选词绝不下探括号内():
    cands = _core_candidates("覆铜板下游需求规模(服务器/通信/消费电子PCB用量)")
    assert "服务器" not in cands and "通信" not in cands
```

实测过 `服务器` 在真实公告语料里出现 18 次。没有这条断言，将来谁把提取
「改进」成下探括号内，会悄悄多出一个 18 次命中的巧合证据，而测试全绿。

其余：

以下期望值**全部由本 spec 的代码实测得出**，不是推演（草稿区跑过）：

- 本轮 7 个真实标签：
  `覆铜板下游需求规模(服务器/通信/消费电子PCB用量)` → `[整串, 覆铜板下游需求规模]`；
  `产能利用率(稼动率同比变化)` → `[整串, 产能利用率]`；
  `原材料成本(铜箔/电子级玻纤布/环氧树脂价格)` → `[整串, 原材料成本]`；
  `产品结构升级(高端CCL如M6/M7/AI服务器用板占比提升)` → `[整串, 产品结构升级]`；
  `汇兑损益(出口业务人民币兑美元波动)` → `[整串, 汇兑损益]`；
  `公司覆铜板市占率` → `[公司覆铜板市占率]`；
  `覆铜板平均单价ASP` → `[覆铜板平均单价ASP]`
- 仓库规范名：`有效产能变化率` → `[有效产能变化率, 有效产能]`；
  `稼动率贡献` → `[稼动率贡献, 稼动率]`；
  `先进封装收入占比提升贡献` → `[先进封装收入占比提升贡献, 先进封装收入]`；
  `原材料及折旧成本变化贡献` → `[原材料及折旧成本变化贡献, 原材料及折旧成本]`；
  `汇率贡献` → `[汇率贡献, 汇率]`
- 无括号、无后缀：`产能` → `[产能]`
- 剥完只剩 1 字则不剥（沿用 `_core_label` 既有行为）：`率贡献` → `[率贡献]`
- 括号不闭合：`产能(稼动率` → `[产能(稼动率]`（头等于整串，不崩）
- 括号占满整个标签：`(稼动率)` → `[(稼动率)]`（去括号后为空，被 2 字下限挡掉）
- 全角括号同样处理：`（全角括号）产能` → `[（全角括号）产能, 产能]`
- **三级阶梯走通**：`先进封装收入占比提升贡献(高端CCL)` →
  `[整串, 先进封装收入占比提升贡献, 先进封装收入]`（这条是唯一同时用上
  L2 与 L3 的例子，必须有）
- 集成：`原材料成本(铜箔/…)` 命中含「原材料成本」的 fixture；
  只含「服务器」的 fixture **不**被 `覆铜板下游需求规模(服务器/…)` 命中
- 顺序：构造一份语料，让较泛的候选词在靠前的容器里出现、更具体的在靠后的容器里，
  断言采用的是**更具体**那个——这条钉住「候选外层」的循环嵌套，把嵌套写反会红
- 现有四条否定语境测试继续绿（回归）

## 七、不做什么

- **不做 `PDF_MAX_PAGES` 与 ②.5 槽位浪费**（第三节已列，是独立的两件事）
- **不引入「窗口里必须有数字」的过滤**（第三节已论证）
- **不下探括号内**（第三节已论证，并有反向断言守）
- **不读 `source_hint`。** 它内容质量很高（模型已写明「这个数去哪找」，还点了
  年报章节名），三个匹配器一个都不读它——但实测显示它引号里的术语在公告语料里
  命中 0–1 次，且那 1 次是章节标题而非数据。它真正的用处是配合
  `annual_sections` 的章节定位，那是另一个设计。
- **不改 `_core_label` 本身、不改 `_valid_hit`、不动 `_SUFFIXES`**
- **不引入任何新的第三方依赖**（`re` 是标准库）
