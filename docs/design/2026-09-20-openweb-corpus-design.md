# 开放网络文档入语料库（子项目 A）

> 缘起：用户提出「在资料收集环节，扩大资料收集的范围，可从互联网搜索行业和
> 公司的相关信息，不仅仅获取研报信息」。本文把它变成可实施的设计。

## 一、现状：联网搜索早就有，但都不进语料库

资料收集实际有三处，只有第一处的产物能被正文引用：

| 环节 | 怎么取 | 产物去哪 |
|---|---|---|
| `_load_external` → `corpus.gather` | 东财研报接口：公司 3 篇 + 行业 4 篇 + 宏观 2 篇 | **`Corpus`** → 宏观定性 / 战略 / 产业链 / 引文归属 |
| `methodology.research` | 真·联网搜索 | 只吐分解式 DSL，原文**不入库** |
| `gaps.collect` → `web.search` | 真·联网搜索，按单个因子 | `Finding` 列表 → 判断项依据，**不入库** |

所以准确的问题描述不是「没有联网能力」，而是**`Corpus` 里只有券商研报**。
而 `Corpus` 是模型唯一能引用的外部文字池（`external.py` 那句「模型只能引用
这里面的东西」是硬契约，`verify()` 要求引文逐字出现在 `d.text` 里）。

结果是：战略、产业链、宏观定性三节的全部外部依据，来自一类有立场、有时效、
本身可能就是错的来源——券商研报。这正是 `external.py` 开篇要解决的那个问题
（「没有一句话来自公司和交易所之外」）只解决了一半。

### 为什么现有的两处联网搜索接不进 Corpus

不是忘了接，是**接不上**：

    Document.text    代码抓回来的全文    → verify() 可逐字核验
    Finding.claim    模型转述的一句话    → 只有 URL 是模型给的，正文从未抓回

`Finding` 进不了正文引用，不是分级问题，是**证明力的种类**不同：一个能回答
「这句话在不在那个网址上」，另一个不能。

## 二、范围拆分

用户确认的四个缺口落在两套机制上，另有一个已知被阻塞的：

- **子项目 A（本文）**：开放网络文档入语料库。覆盖「定性三节的第三方事实」
  「公司层面的动态」「行业上下游与同业的文字面」。
- **子项目 B（不在本文）**：因子采集的搜索面，以及用 A 造出的抓取器把
  `Finding` 从「模型说它在这个网址见过」升级成「代码确认这句话在这个网址上」。
  **必须建在 A 之上**——反过来做，B 要自己造一遍抓取器然后被 A 推翻。
- **子项目 C（不做）**：非上市与海外同业的定量数据。这是 comps 的数据源
  问题，且路线图的 Plan 4 已因同类数据源缺失挂着。

## 三、架构

新文件 `ir_agent/sources/openweb.py`。产物汇入**同一个 `Corpus`**。

```
_load_external
  ├─ corpus.gather                     研报（不变）
  └─ openweb.gather                    ← 新增
        ① discover(client, …)  →  候选清单    模型一次调用，只给网址
        ② fetch(candidate)     →  Document    代码 requests 抓 + 正文提取
        ③ tier_of_url(最终URL) →  Tier        代码观测的域名
        └─ corpus.add_if_visible(doc)          时点守卫
```

**`discover` 与 `fetch` 的分工是这份设计的地基。** 模型只决定「去哪个网址」，
正文由代码抓回，模型不经手一个字——与 `reports.py` 的 `search()` / `fetch_text()`
完全同构。正因为如此，开放网络文档才有资格进 `Corpus`：不是放宽了契约，是
用同一条契约接了一个新来源。

下游三节（`strategy` / `value_chain` / `macro_view`）与 `external.attribute()`
的引文归属**一行不用改**——它们已经在吃 `r.corpus`，混入的文档靠 `Tier` 区分
可引用范围。

### 接在哪里：不能进确定性层

`_load_external`（研报入库）住在 `_analyse_facts` 里，而那一层的不变量写在
它自己的 docstring 上：**「不调模型，因此两个阶段都要跑」**。

`openweb.discover` 要调模型，**不能放进去**。硬塞的后果有两个，第二个是
真正致命的：

1. 成本翻倍——两个阶段各跑一次
2. 第二阶段可能取到与第一阶段**不同的文档**，于是第一阶段正文里写下的外部
   引文，在第二阶段核验不过

第 2 条是本项目已经吃过的那类亏（判断项的依据没跨阶段存活，第二阶段被自己的
闸门拒掉）。根因同一个：**一个不可复现的产物被放在了会被重跑的位置上。**
`corpus.gather` 能待在确定性层，是因为东财接口同 as_of 返回同一批研报；
`discover` 没有这个性质，而且网页本身也会变。

**接入点：`_analyse_facts` 之后、`_analyse_qualitative` 之前。** 这个位置同时
满足三个约束——研报已入库（去重要用）、下游定性三节还没跑、`research_client`
与 `meth.industry` 都已就绪。

### 跨阶段：第一阶段落盘，第二阶段读回

第一阶段把抓到的文档**连同正文**落盘（`out/<code>/openweb.json`）；第二阶段
直接读回构造 `Document` 入 `Corpus`，**零模型调用、零网络请求**。

存全文而不是只存网址：照网址重抓，页面改一个字引文核验就挂。这与「能重算的
就不要存」不矛盾——`discover` 的结果**重算不出来**，正是该存的那一类。

落盘文件缺失或损坏时：第二阶段不重跑 `discover`（那会引入第一阶段没有的
文档），照常继续，清单记「开放网络资料未跨阶段存活，外部引文可能核验不过」。

### 主题槽位

代码写死五个通用槽位：

```python
SLOTS = ("行业规模与增速", "政策与监管", "竞争格局与份额",
         "上下游价格与供需", "公司重大动态")
```

模型可按行业特性**追加**槽位（白酒的批价、半导体的稼动率这类槽位清单预先
枚举不完）。追加的记为「额外发现」，**不参与缺口判定**。

### `discover` 的行格式

与 `web.py` 的 `发现:` 行同一套机制（`lineparse.keyed`），不新造语法：

```
候选: <槽位> | <标题> | <网址> | <发布机构> | <发布日期 YYYY-MM-DD>
```

解析规则，与 `parse_findings` 逐条对齐：

- 少于 5 段 → 整条丢弃（不存在「4 段也合法、日期可选」的分支）
- 网址解析不出 → 整条丢弃
- **日期解析不出 → 整条丢弃**。这是第五节「`Document.published` 保持 `date`」
  能成立的前提：进到 `fetch` 的候选一定带着一个可解析的日期，代码提取到 meta
  日期时覆盖它，提取不到时用它——任何一条路径上都不存在「日期不明」状态
- 槽位不在 `SLOTS` 里 → 收下，记为「额外发现」，不丢弃

固定槽位存在的唯一理由是**让代码说得出缺了什么**。这是本项目贯穿始终的
原则（`research.py` 模块注释、`_load_external` 里那段关于一致预期为空的
长注释）：只列已完成的部分，读者会以为资料是全的。没有预期就没有缺口——
如果主题全由模型自由发挥，代码永远报不出「这次没取到政策原文」。

槽位固定的代价是覆盖面被槽位限死，「模型可追加」正是为这个代价留的出口；
而缺口口径仍由固定槽位定义，不随模型每轮的发挥浮动。

## 四、分级：新增 `tier_of_url`，不动 `tier_of`

```python
def tier_of_url(url: str) -> Tier:
    """按代码观测到的最终域名分级。"""
```

**为什么不复用 `tier_of`。** 现有 `tier_of` 吃的是**模型自报的机构名字符串**，
正因为输入不可信，它被真实来源名打穿过三轮（证券时报网 / 新浪证券 /
Securities Daily / 中国 IDC 圈），最后退守到「白名单全称 + 修饰词」，并在
函数注释里写死了禁止再加模糊规则。

子项目 A 的输入**不是同一种东西**：URL 是代码自己请求的，跟完重定向后的最终
域名也是代码观测到的。模型编不了域名——编了代码就抓不到那个页面。

于是这不是替换判别器，是**给一个不同的输入配一个不同的判别器**。域名这个
输入允许一件字符串输入绝不允许的事：后缀匹配。`.gov.cn` 是受管制注册后缀，
`stats.gov.cn` / `miit.gov.cn` / `csrc.gov.cn` 天然全部命中，一条规则顶一张
白名单。

**`tier_of` 一行不动**，继续管 `Finding`。两者输入的可信度不同，合并等于把
其中一个的教训套在另一个没被验证过的输入上。

### 判别规则

1. 主机名以 `.gov.cn` 结尾（或等于 `gov.cn`）→ `OFFICIAL`
2. 主机名命中 `_OFFICIAL_HOSTS` / `_SELLSIDE_HOSTS` 域名白名单 → 对应档
3. 其余一律 `MEDIA`

白名单怎么建，规则说死，**域名本身不在 spec 里凭记忆写**：

- `.gov.cn` 由规则 1 覆盖，`_OFFICIAL_HOSTS` 只需列非 `.gov.cn` 的机构
- 候选来源是 `web.py` 已有的 `_OFFICIAL_CN/_OFFICIAL_ASCII/_SELLSIDE_CN/
  _SELLSIDE_ASCII` 四张机构名白名单——那批机构是已经论证过分级的，缺的只是
  它们的注册域
- 每个注册域**实施时逐条核实**（访问该机构官网确认），核实不了的**不写进
  白名单**。写错一个域名的后果是把一个不相干的站点拔成 OFFICIAL，正是本节
  代价不对称里「危害」那一侧；漏写一个只是它落 MEDIA，是可接受的召回损失

**要支持新来源，往白名单加注册域，不要碰判别逻辑本身**——这条与 `tier_of`
的维护约定一字不差。

两条硬性约束：

- **匹配的是代码跟完重定向后的最终 URL**，不是模型给的 URL。模型给一个
  `gov.cn` 链接、实际 302 到博客，分级按博客走。
- **主机名匹配必须锚在注册域边界上**：等于注册域，或以 `.注册域` 结尾。
  绝不裸子串——`semi.org` 不得命中 `evil-semi.org.cn`。这是 `tier_of` 那
  三轮教训在域名形态上的对应物，写成不变式测试守住。

代价不对称与 `tier_of` 一致：拔高是危害（一个博客单独支撑一条正文事实），
压低只是召回损失（需要再凑一条来源）。**判不出来落 MEDIA 是正确行为。**

## 五、发布日期

**用户决定：信模型报的日期。**

记录性异议（不改变决定，只是记下来）：模型报错日期在实跑里影响小，但在历史
回测里，一篇 2026-09 的政策原文若被报成 2026-03，就会以合规身份通过
as_of=2026-06 的守卫——正是 `external.py` 说的「静默地把未来讲给过去听」。
`web.py` 的 `Finding.published` 字段注释记着同一类事故换来的规矩：不留
`date | None` 出口，因为编排层迟早会写出 `published or as_of` 这种兜底。

**折中处置（不丢弃、不损召回）：**

- 代码优先从页面 meta 标签提取（`article:published_time` 等），提到就**以
  代码为准**，覆盖模型报的值
- 提不到才用模型报的日期
- `Document` 上标出**日期来源**，清单写「其中 N 篇发布日期由模型给出，未经
  代码核验」

这既不引入会失败的闸门，也不让不可核验的时点声明隐身。与「叙事不参与校验、
但代码实测贡献并列印出」是同一条处置思路：**不可核验的东西不该独占版面。**

`Document.published` 的类型**保持 `date`，不改成可空**——模型总会给出一个
日期，提取不到时用它，不存在「日期不明」这个状态。那个类型口子不能开。

## 六、正文提取、去重与规模

**不引入新依赖。** `bs4` 本机装了但项目一处没用，且仓库没有依赖声明文件，
新增 import 意味着别人的环境可能跑不起来。用与 `reports.py` 的 `fetch_text`
同构的正则去标签法，额外显式剔除 `<script> <style> <nav> <header> <footer>`
整块——开放网页的噪声比东财的 `ctx-content` 块大得多。

**按最终 URL 去重**，避免与研报语料库重复入库。

**规模（用户定：中等档）：**

- `discover` **一次** client 调用，模型把所有槽位的候选网址一起给出
- 每个固定槽位最多 **2 篇**，总量上限约 10 篇
- 每篇进提示词截断 **2000 字**

**入库存全文，进提示词截断。** `d.text` 现在是一字不截地进三个模块的提示词
（`strategy.py` / `value_chain.py` / `macro_view.py` 各一处），研报走
`ctx-content` 块长度天然可控，开放网页可能几万字，且同一批文档会同时压到
三个模块上——撑爆是三倍的。

截断不会让核验误杀：`verify()` 用的是全文，模型只能引用它看得见的那一段，
而那一段必然在全文里。

**抓取行为：** 只抓公开页面，带 UA，遵守超时；不绕反爬、不抓需登录或付费的
页面。抓不到就是抓不到，如实记入清单。

## 七、错误处理（全部不阻断）

| 情形 | 处置 |
|---|---|
| 抓取失败（超时 / 403 / 404） | 该篇不入库，清单记「N 篇抓取失败」 |
| 正文提取为空 | 同上 |
| 发布日晚于 as_of | `add_if_visible` 记入 `skipped`，不中断整批 |
| 某个固定槽位一篇都没有 | 清单记「<槽位>：未取到」 |
| `discover` 整体失败 | 研报照常入库，清单记「开放网络采集未执行」 |
| 模型未开联网工具 | 与 `web.search` 同一条约定，见下 |

**联网工具这条单独说。** 调用方必须传
`make_client(tools=["WebSearch", "WebFetch"])`——不开不会报错，只会安静地什么
都搜不到。`full.py` 里已经有一个这样的 `research_client`（给 `methodology` 与
`gaps` 用的），`openweb.discover` 复用它，不新建。

一条都不阻断整轮研究。资料收集的失败最坏后果是「这一节缺外部印证」，而不是
「整轮分析作废」。

## 八、测试

- 固定槽位一篇没取到 → 缺口能被报出，且**不影响其余槽位入库**
- `tier_of_url` 注册域边界：`evil-semi.org.cn` 必须落 MEDIA（不变式测试）
- `tier_of_url` 跨档白名单条目互不为子域（不变式测试，与 `tier_of` 同款）
- 重定向：模型给 `gov.cn` 链接、实际 302 到博客 → 按最终域名落 MEDIA
- 发布日晚于 as_of → 被 `add_if_visible` 挡下并计入 `skipped`
- 日期来源标记：meta 提到 → 标代码提取且覆盖模型值；提不到 → 标模型给出
- 抓取失败一篇 → 其余照常入库，清单记录失败数
- 截断 2000 字后，模型引用截断段内的文字仍能通过 `Corpus.verify`
- 同一 URL 已在研报语料库中 → 不重复入库
- `discover` 抛异常 → 研报语料库不受影响，清单记录
- **跨阶段**：第一阶段落盘 → 第二阶段读回，文档逐字还原（正文、Tier、
  发布日、日期来源全部对得上）
- **第二阶段不调 `discover`**：落盘文件存在时零模型调用；落盘文件缺失时
  也不调，只记清单（守住「第二阶段不得引入第一阶段没有的文档」）

## 九、不做什么

- **不做子项目 B**（因子搜索面扩大、`Finding` 引文代码核验）——建在本项目的
  抓取器之上，做完 A 单独开一轮
- **不做子项目 C**（非上市 / 海外同业的定量数据）——数据源未解决
- **不改 `tier_of`**——它管的是另一种输入
- **不把 `Document.published` 改成可空**——那个口子的危害已有记录
- **不绕反爬、不抓需登录或付费的页面**
- **不让资料收集的失败阻断整轮研究**
