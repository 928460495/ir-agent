# 第一阶段流程重构设计

## 目标

把第一阶段从「一次调用跑完、只在结尾有一道人工门」改为**四次调用、三道人工门**，
并把多空辩论从「批判已成稿的正文」改为「两个子 agent 采集对立证据、辩出一个带数值
区间的平衡点」。

第二阶段（`--value`：建模 → 完整研报 → 辩论 → 回写）**不变**。

## 为什么改

现状的两个问题，都是实跑暴露的：

1. **人只在最后一道门介入，而那时资料与结论都已固定。** 实测（生益科技 2026-10-06）：
   批准清单第 37 行那张合成表显示五年营收 8.05 倍、隐含份额 39.2%，批准人签了名，
   我也没看。资料来源从未经人核验 —— 而其中「em_macro / eastmoney_report 缺原始接口
   快照」这条告警已经连续六轮出现，始终只在终端一闪而过。

2. **辩论批判的是成稿，而不是证据。** 它能抓住「这句话站不住」，抓不住「这批证据
   被单向挑选过」。多空双方各自采证，才可能暴露证据选择本身的偏向。

## 新流程

```
① --analyse out/X
   取数与事实账本 → 定量采集 → 语料库入库 → 定性分析
   产物: sources.md / sources.json / openweb.json / announce.json / pdf/ / state.json
         dashboard.html / model.xlsx
   【门①：来源核验】verified_by

② --brief out/X --verified-by <名字>
   多空辩论① → 方法论预研 → 因子定向采集 → 多空辩论② → 撰写简报
   产物: stance_a.{md,json} / drivers.md / stance_b.{md,json} / brief.md / review.md
         dashboard.html / model.xlsx（重新生成，补进「因子数据」一节）
   【门②：结论核验】reviewed_by

③ --assume out/X --reviewed-by <名字>
   AI 填判断项 → 算术后果 → 结构审查 → 假设辩论
   产物: assumptions.{md,json}
   【门③：判断项核实】approved_by

④ --value out/X --approved-by <名字>
   建模 → 完整研报 → 辩论 → 回写（不变）
```

每家公司 **4 次命令、3 个签名**。

已知代价：这个项目记着一条教训 ——「门加多了人会开始机械点同意」
（`test_分解式立刻落盘且说明可覆盖`）。三道门的风险是人在每道门上都只扫一眼。
对策只有一个且不在代码里：三道门审的东西互不重叠（来源 / 结论 / 数值），
谁也替不了谁。

## 阶段间交接：复用现成机制，不新建

每次调用的开头都是「重建确定性层（不花模型钱）→ 读回上一阶段的模型产物 → 继续」。
这正是 `--value` 已经在做的事。

| 要跨调用传递的 | 办法 |
|---|---|
| 事实账本 | 每次调用 `run()` 重建 |
| 派生事实（industry./macro./comps.） | `_analyse_facts` 重建，不调模型 |
| 定性分析结果 | `state.json` 的 `md` / `pr`（已在存） |
| 外部语料与公告 | `openweb.json` / `announce.json` + `_restore_announce`（已能读回） |
| 年报 PDF | `pdf/` 缓存（已有） |
| 多空辩论产物 | `stance_a.json` / `stance_b.json` —— **新增**。`stance_b.json` 必须从第②次调用传到第③次，判断项要用那组三元组做候选输入 |
| 分解式 | `drivers.md`（已有往返格式，人可编辑后读回） |
| 看板与工作簿 | `dashboard.html` / `model.xlsx` —— **第①②两次调用各生成一次**。它们不调模型、成本近零，而门① 核来源的人需要一个交叉核对的入口；第②次再生成一遍是为了把「因子数据」那一节补进看板 |
| 签名 | 与 `--approved-by` 同一套：参数缺失即拒绝运行。**校验排在取数之前** —— 今天 `--approved-by` 的 CLI 校验排在 `run()` 之后，忘了署名的人要等整轮取数（几千条事实、三表勾稽）跑完才被告知。三道门的签名校验一律紧随 `parse_args`。另：三处都要有函数层的第二道校验（今天 `run_brief` 那一处没有，另两处有） |

**第②次调用的五个模型环节逐个立刻落盘**（`stance_a.md` → `drivers.md` →
`stance_b.md` → `brief.md`）。它串了五个模型环节，而今天的实测里这五个各自都失败过；
没有中间落盘点的话，失败会丢掉已完成的部分。

## 多空辩论（新模块 `ir_agent/stance.py`）

`debate.py` 不动 —— 第二阶段的成稿辩论仍在用它。

### 三个 agent，一轮三次调用

```
多方 agent：从给定证据里挑出支持更高估值的，逐条给依据
空方 agent：从同一批证据里挑出不利的，逐条给依据
裁决 agent：对质两侧材料，给出平衡点
```

双方拿到**同一份**证据（事实清单 + 语料库 + 定性结论），任务相反。

### 两轮的产物形态不同

| | 辩论①（预研之前） | 辩论②（因子采集之后） |
|---|---|---|
| 可用输入 | 定量事实 / 语料库 / 定性结论 | 以上 + 因子采集结果 |
| 产物粒度 | 按驱动主题（需求/价格/成本/份额/政策） | 按因子 |
| 产物形态 | 文字平衡结论 | `(空方值, 平衡值, 多方值)` 三元组 + 各自依据 |
| 下游 | 预研设计分解式的框架输入 | 判断项三档的候选输入 |
| 落盘 | `stance_a.{md,json}` | `stance_b.{md,json}` |

### 约束：能用代码查的和只能靠判断的分开

| 约束 | 谁来查 | 阻断？ |
|---|---|---|
| 两侧每条证据的依据（FACT 占位符 / REPORT 引文 / EXTERNAL URL+引文+日期） | 代码 `basis.validate` | **不阻断**，核验不过的逐条标注 |
| 平衡值落在两侧之间：`空方值 ≤ 平衡值 ≤ 多方值` | 代码 | **阻断**，驳回重试 |
| 判断项偏离平衡三元组时，该行必须填 `deviation` | 代码查**存在性** | **阻断** |
| 偏离的理由站不站得住 | 结构审查（第 3 道） | 不阻断，标注 |

**为什么证据核验不阻断**：实测三场辩论被契约杀掉（占位符缺失、裸数字、
「分位数之后多写一个单位」），每次损失一整场。而「核验 + 标注、不阻断」是这个项目
已经在用的模式 —— 判断项那边早就这么做：「N 行依据未能逐字核验（已标注，未阻断，
需人工复核）」。它不降低成功率，又保留检出能力：核验不过的那几条当场标出来，
人在门②一眼能看到。

**为什么平衡值要阻断**：裁决者不能自己造数，它只能在两侧划出的区间里选。
这是这套设计里唯一能确定性保证的东西 —— 平衡点对两侧可问责。

**`deviation` 的作用**：让「无视辩论」和「有理由地偏离」在产物上长得不一样。
没有它的话，判断项中性档 18%（平衡点 12%）这件事，无论是模型看到了因子细节
而上调、还是模型压根没读辩论，产物上完全一样。同构的实测案例：判断项被锚定覆盖
（批准 19.12% → 实际用 −1.58%）之所以能被人看见，唯一原因是代码专门为它生成了一行
说明。

## 语料库入库：挑选改为确定性，上限移到提示词层

**这一节是顺序调整逼出来的，不是附带改进。** 今天 `_load_announce` 的
`factors=` 参数来自 `meth.decompositions`（`full.py:1554`），`_load_openweb`
的 `industry=` 来自 `meth.industry`（`full.py:1529`）—— 预研一挪到它们之后，
两个参数都空了。

`industry` 好办：它其实是 `taxonomy.fetch_all()` 的 `me.path`，**确定性查表、
不是模型输出**，抽成一个助手即可（`_peer_names(code)` 已在用同一条路）。

`factors` 是真问题，而解法不是给它找个别的上游信号。

### 约束放错了层

公告这一步的真实形状：

```
① 取清单（便宜：标题 + 披露日 + URL，一次巨潮接口）
② 挑选  ← 今天在这里调模型，而它需要因子
③ 下载正文（贵：逐篇抓 PDF + 抽文本）
```

② 存在的理由是 ③ 贵。而 `MAX_ANNOUNCEMENTS = 8` 这个数的理由，注释自己写着
「同一批文档会同时压到战略/产业链/宏观定性三个模块的提示词上，长度是三倍的」
—— **那是消费方的约束，被实现成了生产方的上限。**

全仓库遍历 `corpus.docs` 的地方只有三类：

| 位置 | 做什么 | 语料库变大的后果 |
|---|---|---|
| `strategy.py:259` / `value_chain.py:321` / `macro_view.py:238` | 把**全文**喂进提示词 | 提示词变长 ← 上限的真实理由 |
| `gaps.py:312` / `gaps.py:340` | 按因子做**全文检索** | **召回提高** ← 正是要的 |
| `attribution.py:117` | 只读 publisher 名单 | 无 |

`Evidence` 只拿语料库做查找（`find` / `publishers` / `catalogue`），**不把任何
文档正文放进提示词**。所以语料库变大不会撑长撰写、辩论或第二阶段的提示词；
那三个定性模块是唯一的正文消费方，而它们只在第一阶段跑（第二阶段的 `md` 从
`state.json` 读回，不重跑 `_analyse_qualitative`）。

### 新做法

1. **② 改为确定性标题分类，零模型调用。** 实质类（扩产/投产/产能/价格调整/
   重大合同/对外投资）vs 程序类（股东大会通知/董事会决议/独董声明/会计师
   改聘/业绩说明会通知）。这正是现有提示词里那段硬性要求的内容 ——
   **它本来就是按公告类型分的，与因子无关。**
2. **入库条数放宽到 15–20 篇**（实质类按披露日倒序）。
3. **三个定性模块各改一处**：不再 `for d in corpus.docs` 无差别全喂，改为
   COMPANY 级取最近 8 篇、其余分级照旧全给。上限回到它该在的地方。
4. **因子定向挪到消费端**：`gaps._match_announce` 按因子做全文检索，搜全部
   15–20 篇。**那一步本来就是代码做的、确定性的，而且此时因子已经知道了。**

### 这解决了什么

- 循环消失 —— 公告入库彻底不依赖预研
- 少一次模型调用
- **召回反而提高**：因子定向能搜的池子从 8 篇变成 15–20 篇。牧原股份那次
  因子搜不到证据，有一半原因是可搜的池子太小
- 挑选从**不可逆的入库时点**移到**可重做的消费时点**

### 代价与风险

- **下载 15–20 篇比 8 篇慢。** 纯时间不是钱；`_download` 有 `cache_dir`
  缓存，重跑不重抓。
- **标题分类器是新代码，会误分类。** 失败模式温和：误判成程序类 = 少一篇
  （与今天模型漏挑同一后果）；误判成实质类 = 多下一篇无用 PDF。
  **不设「可疑就调模型兜底」这类分支** —— 那会把确定性又换回去。
- **范围扩大到三个此前不打算碰的文件**（`strategy.py` / `value_chain.py` /
  `macro_view.py`）。它们不在「第二阶段一行不改」那张清单上，但要各自回归。

### 不做

- **不把公告入库搬进 `_analyse_facts`**（确定性层），尽管挑选确定性化之后
  原本禁止它的理由已经消失。`_load_announce` 的 docstring 写的是「本函数要
  调模型挑标题，放进去第二阶段会重新挑选、挑出与第一阶段不同的公告，第一
  阶段正文里的公告引文因此在第二阶段核验不过」—— 确定性分类器没有这个性质，
  `_search(code, start, as_of)` 固定 as_of 返回同一份清单。
  但搬进去会让第二阶段每轮重抓 PDF，而收益只是省掉一套正在正常工作的落盘
  读回机制（`_restore_announce`）。这是独立的清理，不混进这次重构。
- 不动 `ANNOUNCE_MONTHS = 12` 的检索窗口。
- 不动 `openweb` 那一侧的挑选逻辑 —— 它的 `industry` 参数改为确定性查表后
  就没有其它依赖了。

### 修订（2026-10-13 生益科技试跑后）：按交易所分类代码分档，不按标题认字

第一版按标题关键词判程序性（黑名单）、按时间取最近 20 篇。试跑时入库的 20 篇
里 15 篇是程序性噪声，而投资建设高性能覆铜板项目、年度业绩快报、两次业绩预增
全被挤掉。两个原因叠加：

1. **2024 年新《公司法》把「股东大会」改名「股东会」**，标题词表与
   `cninfo.classify` 同时失效。这不是生益科技特殊，是所有公司同时中招 ——
   **按标题认字对措辞变化天然脆弱。**
2. **上限把「放过」换算成了「丢掉」。** 当时为黑名单辩护的理由是「误判成实质
   类 = 多下一篇无用 PDF（便宜）」；有上限时这个推理不成立，每误放一篇噪声就
   挤掉一篇有用的。

**改为（方法一 + 方法三）：**

- **按巨潮 `announcementType` 分档**：披露系统按公告性质给的分类代码，与公司、
  措辞都无关。实证：`011905` 同时收了贵州茅台的「股东会决议」与长电科技的
  「股东大会决议」。第一档（对外投资、收购资产、业绩预告快报、经营数据）、
  排除（股东（大）会、中介意见、交易异常、权益分派、定期报告、董监事会决议、
  章程制度等程序性）、其余第二档。
- **代码表的依据是实证**：沪深上市公司这套代码没找到公开的官方定义
  （JR/T 0220.1—2021 是新三板挂牌公司的标准，文中没有这套编码）。表中每个码
  都在快照里 30 家公司、7301 条公告上逐个看过跨公司样本。
- **排除要保守、默认保留**：判错一个码，排除一侧丢文档（无声），保留一侧只多
  下载几篇。无类型码或未知码按第二档保留，并在门① 说出来。
- **入库不再按数量挑**：安全上限 150（30 家公司 12 个月窗口入库中位 66、最大
  140），按档排序**之后**才截断，只截第二档的尾巴，截了多少要说出来。
- **进提示词的 8 篇先按档、再按新旧**（`Corpus.prompt_docs`）。

生益科技真实候选上：136 条 → 排除 85、第一档 8、第二档 43，入库 51 篇；第一档
正好 8 篇，五篇关键公告全在。代码偏粗的代价：第一档混进「委托理财」（`011705`）
与「会计政策变更」（`012305`）。


## 方法论预研的框架重构

**挪了位置就必须重写提示词，不是加个参数。** 这一节单独写，因为它是本次
重构里唯一一处「同一个环节、问的却是另一个问题」。

### 现状：它手里只有行业分类

`methodology.PROMPT` 的全部输入是**申万行业分类路径 + 股票代码**，再无其它。
它不接事实账本、不接语料库、不接定性结论 —— 因为在旧顺序里它排在最前面，
那时这些都还不存在。

于是它只能问一个**行业级的通用问题**：「这个行业靠什么赚钱」。产出是
「这个行业怎么运转」，不是「这家公司此刻的争议在哪」。

产出形态（必须算术闭合，这部分**不变**）：

```
分解: 营收   | 乘 | 因子名:单位:数据线索:检索词 | …   单位一律「变化率」，2–5 个
分解: 毛利率 | 加 | 因子名:单位:数据线索:检索词 | …   单位一律「pp」
陷阱: <一句话>
```

现有硬约束同样**不变**：pp 不进乘法链；写不出单位的项不许进来；营收乘法链
禁占比/比重/结构类因子（市占率例外）；每条 2–5 个因子。

### 新位置之后它手里多了四样东西

| 新输入 | 从哪来 |
|---|---|
| 事实账本（两三千条） | 取数 + `_analyse_facts` 的派生层 |
| 年报分节 | `r.sections` |
| 语料库 | `Corpus`：东财研报（SELLSIDE）、巨潮公告（COMPANY）、开放网络（OFFICIAL/SELLSIDE/MEDIA），每篇带全文与分级 |
| 定性结论 + 辩论① 平衡点 | `state.json` 的 `md`；`stance_a.json` 按需求/价格/成本/份额/政策五个主题的文字平衡结论 |

该问的问题因此变成：

> **就多空双方争执的这几个点，这家公司的营收和毛利率该怎么分解，
> 才能把争议落到可测的因子上？**

### 五处实质改动

**(a) 分解式的选择标准：从「行业公认」改为「能承载争议」**

旧标准是卖方怎么看这个行业。新标准多一条：分解式要能承载辩论① 列出的主题。
多空在「份额」上分歧最大，分解式里却没有份额因子，那么辩论② 无从给出三元组、
判断项也无从反映分歧 —— 整条链在这里断掉，而产物上看不出来。

**覆盖约束：标注，不阻断。** 代码按主题逐个查「有没有一个因子的标签或数据
线索提到它」，把结果印在 `drivers.md` 顶部与终端：

```
辩论① 主题覆盖：需求 ✓（高端覆铜板出货量同比）· 价格 ✓（平均单价变化率）
                 成本 ✓（铜箔采购价变化率）· 份额 ✗ · 政策 ✗
⚠ 2 个辩论主题未进入分解式（已标注，未阻断，需人工在门② 复核）
```

为什么不阻断：与多空证据核验同一条理由 —— 这是**语义判断**，代码只能查
「某个词有没有出现在因子标签里」，而「份额这件事有没有被这个分解式覆盖」
要靠读。实测教训就在手边：隐含份额检查想用算术判断一件该由语义判断的事，
10 份存档上 10/10 惰性。标注不阻断保留了检出能力又不误杀。

已知代价：模型可以无视辩论① 而照旧给行业通用分解式，这时只有一行标注拦着。
它落在门② 的 `review.md` 上，和「证据核验不过」并列。

**(b) 检索词：从「靠告诫」改为「靠数据」**

现在的提示词花了一整段劝模型不要给泛词，还得举实测数字（生益科技 8 篇公告
8.9 万字里「覆铜板」98 次、「产能」31 次、「服务器」18 次是反例；「原材料
成本」2 次、「铜箔」6 次是正例）—— 因为那时候语料库不存在，模型只能凭猜。

现在语料库已在手。**代码可以直接算出命中次数反馈给模型。**

要紧的是**反馈哪几个词**。`gaps._core_candidates` 的候选是四级阶梯：

```
L1 整串标签 → L2 去掉括号及其内容 → L3 头再剥后缀 → L4 模型给的检索词
```

**检索词在最底端，不是顶端** —— L1–L3 全部落空才轮到它。所以只反馈检索词
的命中次数，是在优化用得最少的那根杠杆。必须把 L1–L4 四个候选词的命中次数
一起给它看，它才知道这个因子究竟会靠哪一级命中、以及那一级准不准。

机制：预研产出后，代码对每个因子算四级候选词在「年报分节 + 研报 + 公告」里
的命中次数，**原样印进 `drivers.md` 的标注段，不反馈给模型、不设阈值。**

**不反馈**：省一次模型调用。检索词选得好不好，门② 的人看得见次数就能判断，
而他本来就要看 `drivers.md`。

**不设阈值**：原本想按实测取「命中 > 10 次判为泛词嫌疑」—— 那组实测只有
五个样本（生益科技 8 篇公告 8.9 万字里覆铜板 98 / 产能 31 / 服务器 18 是
反例，原材料成本 2 / 铜箔 6 是正例），而公告篇数与字数每家公司都不同，一个
绝对次数的阈值换个行业就不对。**把次数原样印出来让人判断，比印一个靠不住的
判语好。**

**(c) 数据线索：从「去哪找」改为「有没有」**

旧提示词要求「数据线索要具体到年报哪一节 / 哪类研报 / 哪个行业数据源」——
因为采集还没发生，只能指方向。现在账本里哪些 key 已经有、语料库里有哪些
文档，都是已知的，可以让它优先分解成**已有数据能支撑的因子**。

这直接决定下游 `gaps.collect` 的命中率。牧原股份那次整个分解式被毁（「公司
出栏量占全国比重」被拒 3 次、`drivers.md` 根本没生成），根子就在预研是盲的。

**(d) 「陷阱」改为「这个分解式会被怎么误用」**

定性分析与辩论① 已经把具体风险摊开了。预研再产一遍行业通用陷阱，要么与它们
重复、要么是空话。改为针对**它自己刚给出的这组因子**：哪个因子容易被双重
计数、哪两个因子实际上不独立、哪个单位换算容易错。这正是下游结构审查
（`factor_review` 的「正交：独立/重叠」一项）要对的账。

**(e) 「先上网搜索」这条前提要重审**

现有 `research()` 的文档字符串专门写着：提示词要求「先上网搜索」，但
`research()` 自己不构造 client —— 调用方若传了不带 `tools=` 的 client，
这条要求形同虚设。

现在手里可能已经有入库的卖方研报。新框架应当：**先用已入库的 SELLSIDE
文档，仅在它们不足时才联网补**。这既省钱，又让预研与简报引用的是同一批
材料（否则预研依据的方法论在语料库里找不到，分解式的来头就无从溯源）。

**这不改 `TIER_RULE[Tier.SELLSIDE]` 那条规矩**（卖方的盈利预测/评级/目标价
不得作为假设依据，只作一致预期对照）。两件事不冲突：预研读研报读的是
**方法论**（这个行业的营收由什么驱动），产出的是分解式的**框架**，不是任何
一个因子的取值。取值仍由辩论② 与判断项各自按原规矩找依据。

### 产物与落盘

`drivers.md` 的格式不变（人可编辑、重跑读回，I2 那条承诺继续成立），顶部
新增两段标注：辩论① 主题覆盖情况、每个因子的四级候选词命中次数。

两段都是**标注**，不参与 `from_markdown` 的解析 —— 人改分解式时不必维护
它们，下次重跑由代码重算。

### 不做

- 不做「覆盖不全就驳回」。理由见 (a)。
- 不把命中次数做成阻断闸门。`drivers.Factor.search_term` 现有的闸门只查
  长度，这一条不改。
- 不改 `Methodology` / `Decomposition` / `Factor` 的数据结构与 DSL 行格式 ——
  改的是提示词、输入与两段标注。

## 修订（2026-10-13 第二次调用试跑后）：因子采集为什么一条都没采到

生益科技 `--brief` 重跑到了门②，但核产物时发现**因子定向采集 6 个因子全部
「无数据」**，`drivers.md` 的命中次数也全部是 0。逐层追下去是三个独立的
缝，外加门② 上两处说错话的标注。共同形状：**上游让模型写了信息，下游没人
读，或者读的方式与写的约定对不上**——两端各自的单元测试都是绿的。

### ① 检索词被写成「检索词Prismark」

格式行 `因子名:单位:数据线索:检索词` 读起来像「字段名:值」，模型把「检索词」
三个字当前缀照抄，6 个因子的检索词全成了 `检索词Prismark`、`检索词铜价`。
年报里 Prismark 实际出现 5 次、市场占有率 1 次，命中次数却印 0；`gaps.collect`
的年报、公告两级拿这个词去搜，必然落空，全部掉到联网那一级。

**改为**：

- 格式行改为写不成前缀的占位写法 `<因子名>:<单位>:<数据线索>:<检索词>`，
  并附一行填好的示例。根因在提示词，先修这里。
- 解析时若检索词以字面「检索词」开头（后可跟 `:`/`：`/`=`），剥掉。只做兜底。

### ② 联网采集：改为「模型综合结论 + 引用文章清单 + 人工复核」

**现状**：提示词要模型写「具体数据的一句话陈述」（允许改写），核实却要求
这句话逐字出现在原页（`openweb.verify_finding`）。两者对不上，15 条发现全部
核实失败、被丢弃，原因还被截到 60 字，门② 上什么都看不到。

**单因子实验**（核心原材料成本效应，$0.47，5 条全部失败）逐条对照原页：

| 失败形状 | 条数 | 例 |
|---|---|---|
| 改写 / 跨段拼接 | 4 | 原页「第五轮提价……相比2025年三季度低点，涨幅高达100%」，模型写「第5轮……较……达100%」 |
| 混进原页没有的细节 | 1（含在上面） | 同一条加了「7628型规格」——7628 在那一页上**根本没有出现** |
| 全角改半角 | 1（含在上面） | 原页 `（玻纤布）`，模型写 `(玻纤布)` |
| 抓回的不是正文 | 1 | 捷配返回阿里云 WAF 的 JS 挑战页，代码当成正文、报成「转述未能核实」——**说错话** |

**决定（用户，2026-10-13）**：模型的一句话可能是跨多篇文章取材后分析判断
得到的结论，**不要求照抄原文**。改为模型给出结论并列出采纳了哪些文章的观点，
由人复核。代码不再判对错，只做机械比对、把要重点看的位置标出来。

**模型输出格式**——结论与文章分开，一条结论可引多篇：

```
文章: 1 | <网址> | <机构> | <发布日期 YYYY-MM-DD>
文章: 2 | <网址> | <机构> | <发布日期 YYYY-MM-DD>
结论: <因子key> | <一句话结论，可综合、可改写> | 依据 1,2
```

文章编号只在本次回答内有效。提示词要求：用 WebFetch 打开文章再下结论；
结论里的数字尽量照原文写法。

**代码做的四件事，全部是标注，不阻断**（唯一例外是第 2 件，那是时点守卫）：

1. **文章打不打得开**：每篇（同一网址只抓一次）抓回正文。抓取失败，或抓回
   文本里一个中文字符都没有（反爬挑战页、外文页面都落在这里），标「代码无法
   打开该文章正文，无从比对」——措辞不能再说成「转述未能核实」。**不绕过反爬。**
2. **时点**：晚于 `as_of` 的文章剔除；一条结论引的文章全部被剔除，这条结论
   丢弃；部分被剔除则保留并注明。没有网址或日期的文章整条丢弃——沿用
   `web.parse_findings` 现有规则，不放宽。
3. **数字有没有出处**：结论里的每个数字（`\d+(\.\d+)?`），到它引用的那几篇
   文章正文里找，标「✓ 文章2」或「⚠ 引用的文章里都找不到」。找的时候：
   文章正文局部做全角→半角（只在这一步做，**不改共用的 `external.norm`**）、
   去掉千分位逗号；阿拉伯数字找不到时，1–99 的整数再按中文数字写法找一次
   （实验里「第五轮」↔「第5轮」）。只核数字，不核措辞——改写的风险集中在
   数字上，措辞差异对估值无影响。
4. **来源分级**：按代码实际抓到的最终域名（`tier_of_url`），不按模型自报的
   机构名。

**落盘与数据流**（「数据跟着流程走」）：

- 抓到正文的文章，全文进 `r.corpus`（`Document`，`published` 是模型给的
  日期，沿用开放网络采集「发布日期由模型给出，未经代码核验」的标注）。辩论②
  与撰写简报因此引的是**文章原文**，不是模型的结论——「不得引用本系统的分析
  结论」那条既有规矩照样成立。
- `factors.json` 改为新结构，带 `"schema": 2`：每个因子的结论列表，每条结论
  带引用的文章（网址、机构、日期、最终域名分级、是否打开、正文）与逐个数字
  的出处标注。读回时没有 `schema: 2` 的旧文件，按「读不回」处理并提示重跑
  `--brief`。
- **第三次调用要能读回文章正文**：`--assume` 从 `factors.json` 读回文章正文，
  并**按（可能被人改过的）结论文字重算数字标注**——人在门② 改了结论，
  标注不能停在改之前。
- 有一条结论（含带 ⚠ 的）的因子，状态为「外部来源」，note 写明「模型综合结论，待人工复核」；没有任何
  结论的仍为「无数据」。
- 因子采集的④分支不再调 `openweb.verify_finding` / `web.supports_value`；
  这两个函数若无其他调用方，实现时一并删除，有则保留。

**门② 呈现**：`review.md` 新增一节「因子联网结论（模型综合，待人工复核）」，
每个因子列结论、引用文章链接与分级、每个数字的出处。带 ⚠ 的结论排在最前。

**门② 复核粒度（决定 B）**：门② 签一次名，覆盖全部结论。有异议的，人直接改
或删 `factors.json` 里对应条目后再签。

**带 ⚠ 的结论在门③（决定 A）**：可以作判断项依据，但该行带标记「依据含 N 个
在引用文章里找不到出处的数字」/「依据引用的文章代码无法打开」。与本项目「标注
不阻断」一贯原则一致——这些 ⚠ 人在门② 已经看过。

### ③ 快照缺口：用实际查到的，不用写死的名单

**门②**：`review.md` 列的是整本账本按写死名单（`manifest.KNOWN_GAPS`，只有
em_macro、eastmoney_report）数出来的缺口；终端审计说的是简报自己引用的 16 条，
来源还有 em_rates——名单里没有它。

**改为**：快照有没有只取决于 `source_id`（`audit.py` 正是逐条 `store.load(
n.source_id)`，跳过 COMPUTED）。拿审计给出的缺失 `source_id` 集合回头筛简报
脚注，逐条列出「渲染值 | key@期间 | 来源」，按来源分组。**不改 `audit.py`**，
第二阶段不受影响。

**门①**：`sources.md` 同一毛病。改为对账本里每个不同的 `source_id`（跳过
COMPUTED）实际 `store.load` 一次，按来源汇总条数。`KNOWN_GAPS` 降为「为什么
缺」的说明文字表，查不到说明的写默认措辞「未保留原始接口响应」。上文门①
示例里写死的「em_macro / eastmoney_report」以实际查到的为准。

### ④ 主题覆盖：模型声明为主，词面匹配兜底

`theme_coverage` 按词面判，报「需求、份额未进入分解式」——实际上「行业产值
同比增速」承载需求，「公司市占率同比变化率」承载份额。提示词已要求模型写
`未覆盖:` 行，但**解析时被丢弃**，`drivers.md` 里也没有这一节，读回即丢。

**改为**：

- 提示词要求对每个主题写一行：`覆盖: <主题> | <因子名>` 或
  `未覆盖: <主题> | <为什么不能因子化>`。
- 两种行写进 `drivers.md` 的原始定义块（`from_markdown` 读回的那段），人改过
  再重跑不丢。`Methodology` 新增一个字段存这些声明。**这修订了上文「方法论
  预研 · 不做」里「不改数据结构与 DSL 行格式」一条**：新增行类型与字段，既有
  `分解:` / `陷阱:` 行格式与 `Factor` / `Decomposition` 结构不变。
- 呈现三档：✓ 模型声明由「X」承载（代码核对 X 确实是分解式里的因子名）；
  ✗ 模型声明未覆盖，附理由；？ 模型没交代——退回词面匹配，注明「仅词面匹配」。
- 代码只标注：声明了清单外的主题、声明的因子名不存在（该主题落「？」）、同一
  主题既声明覆盖又声明未覆盖（标矛盾）。

### ⑤ 模型点名的账本 key 没接到采集环节

上文 (c) 要预研「优先分解成已有数据能支撑的因子」，理由是「这直接决定下游
`gaps.collect` 的命中率」。实现只做到了把账本 key 清单给模型；模型照做了
（数据线索里写了 `industry.revenue_yoy`、`company.market_share_delta`，账本里
确有，是同业 46 家聚合算出），但 `gaps.identify` 拿因子名 slug 出的 key
（`f_行业产值_…`）查账本，永远查不到——这两个因子被当缺口去联网，落「无数据」。

**改为**：

- `gaps.collect` 从数据线索里取出显式声明的 `[[key]]`，与账本 key 集合**精确匹配**
  （见下文收紧；按整词比对，`industry.revenue` 不会误中 `industry.revenue_yoy`）。
  时点守卫照旧：`as_of` 之后才披露的视为没有。
- 至少一个匹配上的因子，状态「已披露」，note 写「账本 `industry.revenue_yoy`
  （模型在数据线索中指向，口径是否一致待人工确认）」，不再往下联网。要人确认
  口径的理由就在本例：因子名写的是「Prismark 口径」，账本是 A 股同业聚合口径。
- 线索里写了形如 key、账本里却没有的，在 `drivers.md` 标出来，不阻断。
- **不改 `Factor.key`**：key 是工作簿行匹配与判断项的锚，换成账本 key 会牵动
  第三次调用与第二阶段；且「口径待确认」本身说明二者不应合一。

### 写实现计划时的四处收紧（2026-10-13）

- **⑤ 只认显式声明 `[[key]]`**，不按「线索里出现形如 `a.b` 的词」绑定。生益科技
  第 60 行线索原文「capex、fixed_asset等账本key……需采集稼动率数据」：提到 capex
  不等于稼动率就是 capex，按出现即绑定会错绑并跳过采集。提示词讲明「只是相关的
  不要写成 `[[ ]]`」。
- **② EXTERNAL 状态值仍为「外部来源」**，「待人工复核」写在 note 里 —— 状态值
  在判断项提示词等多处按字面出现，换值牵连面大而无实际收益。
- **② 第三次调用不把文章放回语料库**：`--assume` 里没有任何环节读语料库，文章
  正文随 `factors.json` 走、供重算数字标注即可。
- **② `factors.json` 补存 `source_excerpt`**：此前漏存，第三次调用里模型逐字引用
  年报摘录会匹配不到（与本节无关的既有缺口，顺带修）。
- `web.Finding` / `parse_findings` / `openweb.verify_finding` / `web.supports_value`
  / `by_tier` 本批**不删**：仍有测试守着、`test_assume.py` 用 `Finding` 构造数据，
  删除连带四个测试文件，另起清理任务。

### 不做

- 不绕过反爬校验。打不开就标「打不开」，交给人在浏览器里看。
- 不改 `external.norm`（实验时曾考虑加 NFKC：改写放开后这条路径不再逐字比对，
  不需要了；`norm` 被四条核实路径共用，不为一处需求改四处）。
- 不做数字以外的语义核对（结论与文章观点是否一致、讲的是不是本公司——实验里
  证券之星那页讲的是胜宏科技的市占率）。这是门② 人的事。

## 失败处置：没有降级，只有重跑或人工补写

**取消全部自动降级。** 任何多空环节失败时流程停止，终端给出两条可粘贴的命令：

```
多空辩论① 未完成：裁决者三次给不出落在两侧区间内的平衡值
最后一稿已落盘：out/X/stance_a_failed_raw.md
已生成待填模板：out/X/stance_a.template.json

  ① 原样重试（模型重抽）
     python -m ir_agent 600183 --year 2025 --brief out/X --verified-by <名字>

  ② 人工补写：按模板填好 out/X/stance_a.json，然后
     python -m ir_agent 600183 --year 2025 --brief out/X --verified-by <名字> --accept-manual
```

`--accept-manual` 读回人填的 JSON，跳过该环节的模型调用，并在产物中记录
「本轮多空输入由 <名字> 人工补写」。

**重跑时已有的 `stance_a.json` / `stance_b.json` 算数。** 与 `drivers.md`
同一条规矩（I2「可覆盖的承诺需要一条读回路径才成立」）：文件在就读回，不再
重抽。要重抽给 `--refresh-stance`。

理由是成本与一致性两条。门② 打回来重跑一次 `--brief`，若每次都重抽，就是
6 次模型调用（两轮 × 多空裁决各一次）全部重做；而人若手改过 `stance_b.json`
的某个三元组，重抽会把那次修改悄悄冲掉 —— 正是 `drivers.md` 当初要堵的
那个洞。同一个仓库里不该有两套规矩。

**不存在「跳过」这条路。** 每份研报的多空输入要么来自模型、要么来自人，不会「没有」。
已知代价：某家公司反复失败时流程会卡住，直到有人手写那份 JSON。

**裁决者被驳回 3 次才交给人工。** 这个次数管的不是「失败还是交人工」——
两者都会发生，只是先后：驳回重写是模型自己纠错，连续 3 次不行才落盘模板、
停下来等人。取 3 而不是 2，是因为多一次模型重试约 $0.3，而交给人工的代价是
一个人手写一份 JSON；现有 `methodology.research` 的默认值同样是 3。

**`--accept-manual` 只对 `--brief` 有意义。** 两轮辩论都在那一次调用里；
`--assume` 没有任何多空环节，这个开关在那儿无物可读。`--assume --accept-manual`
**直接报错退出**，不静默忽略 —— 静默忽略一个用户显式给出的开关，会让人以为
自己的补写生效了。

## 两道新人工门的产物

### 门① `sources.md` + `sources.json`

| 资料类别 | 清单给出 |
|---|---|
| 账本事实 | source_id、接口名、原始响应快照的位置（有/无） |
| 外部文档 | URL、本地缓存路径、抓取日期、来源分级、主机校验是否降级 |
| 公司公告 | 标题、披露日、巨潮 URL、`pdf/` 本地路径 |
| 年报 PDF | 本地路径、页数、是否被 `PDF_MAX_PAGES=30` 截断 |
| 行业/可比 | 同业样本名单（牧原 11 家 vs 生益 46 家，代表性差异要让人看到） |

**已知缺口在这道门显式列出**，不再每轮在终端重复：

```
⚠ 以下来源不具备完整可溯源性（结构性限制，非本轮故障）：
   em_macro / eastmoney_report —— 数字从文本抽出，未保留原始接口响应
   本轮涉及 18 条引用
```

**代码在这道门查**：清单里列出的每个本地文件路径逐个 `stat` 确认真的在磁盘上。
防的是「清单引用了一个从未保存的文件」。内容由人负责。

### 门② `brief.md` + `review.md`

`review.md` 是一张待核清单，把所有「代码没把握」的东西聚到一处：

```
多空证据中代码核验不过的：N 条（逐条列出）
简报引用缺原始接口快照的：N 条（逐条：渲染值 | key@期间 | 来源）
因子联网结论（模型综合，待人工复核）：每条结论 + 引用文章 + 逐个数字出处，⚠ 在前
```

（2026-10-13 修订，详见「第二次调用试跑后」一节 ②③。）

### 三个签名各自落在自己那道门的产物上

```
sources.json   {"verified_by": "xhl", ...}   门① 产出，随 sources.md 一起给人核
state.json     {"reviewed_by": "xhl", ...}   门② 产出
assumptions.json {"approved_by": "xhl", ...} 门③ 产出（已有）
```

`brief.md` 与 `assumptions.md` 各自在顶部印出自己那道门的签名。

**最终研报的附录不改** —— 第二阶段（`_write_full_report`）一行都不动。

**已知代价：这没有解决 spec 原本要解决的那个对外问题。** 半年后有人读这份
最终研报，附录上仍然只有一行「判断项经 xhl 核实」，而那只覆盖 40 行三档
数值；资料来源有没有人核过、简报结论有没有人审过，读者翻不到 —— 他得去翻
`out/X/` 目录里的三个 JSON。三个签名因此只对**项目内部**可见。

这是一个明确的取舍：保「第二阶段一行不改」这条约束的完整性，代价是签名的
对外可见性延后到另一个任务。

## 要改的既有不变量

1. **删掉 `test_预研排在数据采集之前`**。该测试的理由是「先问这个行业靠什么赚钱，
   再按答案去采集数据 —— 顺序反了就退化成『先收集再解释』」。新顺序接受这个代价，
   换取「分解式能基于全部证据与多空结论设计」。
   **必须换上一条新的**：预研仍须排在因子采集之前，否则「按分解式定向采集」无从谈起。
   **这个代价不是无条件接受的**：旧顺序下「先解释再收集」具体兑现在两个参数上
   —— `_load_openweb(industry=meth.industry)` 与 `_load_announce(factors=…)`。
   前者改为确定性查表、后者改为确定性标题分类 + 把因子定向挪到消费端，
   详见「语料库入库」一节。真正接受的代价只剩一条：定性三节读到的公告，
   不再是按本轮因子定向挑出来的那 8 篇。

2. **第一阶段的 `_write_and_debate` 拆开**：撰写留在第②次调用，旧的成稿辩论删除。
   `_debate_and_revise` 不动（第二阶段仍用）。
   **已知损失**：简报从此没有任何自动化环节读它。今天实测里旧辩论抓到的都是成稿层面
   的错（HHI 因果方向倒置、「衰退阶段」无据、「16.5 家」伪精度、「52 亿在建项目」
   无依据）。这几类今后只能靠门②发现。

3. **`methodology.PROMPT` 整条重写**，不是在原文上加一段。见「方法论预研的
   框架重构」一节：输入从「行业分类 + 代码」变成「行业分类 + 代码 + 账本 +
   年报分节 + 语料库 + 定性结论 + 辩论① 平衡点」，问的问题从「这个行业靠
   什么赚钱」变成「就多空争执的这几点，这家公司该怎么分解」。
   **保持不变**：`Methodology` / `Decomposition` / `Factor` 的数据结构、
   DSL 行格式、算术闭合的全部硬约束、`drivers.md` 的往返格式。
   `research()` 要新增可选参数接这些输入，且**不得**破坏「不传就退回
   行业级预研」这条 —— 那是两标量降级路径仍然要走的。

4. **`next_actions` 要认识四个状态**，按产物推断当前停在哪道门，并给出可粘贴的下一条
   命令。它的 docstring 写着「过时的指引是会主动误导人的那种错」。

## 测试策略

- `stance.py` 的纯函数全部单元测试：两侧证据解析、平衡值区间校验（含变异）、
  模板生成、`--accept-manual` 读回
- 阶段切分用**行为测试**而非源码字符串匹配：打掉模型调用，断言每次调用的产物集合
  与停止点。本会话已有四次「结构式断言盯着源码字面量」而误报/漏报的记录
- 门①的文件存在性校验：建临时目录，列一个不存在的路径，断言报错
- `deviation` 存在性校验的变异验证：摘掉检查后对应测试必须变红
- 预研新框架的三项，都用**不调模型**的纯函数测：
  · 辩论① 主题覆盖的标注：给一组分解式与五个主题，断言未覆盖的被逐个列出，
    且**返回的是标注而不是异常**（变异验证：把标注改成 raise，测试必须变红）
  · 四级候选词命中计数：喂一份已知文本，断言 L1–L4 四个词各自的次数，
    并钉住「检索词是第四级而不是第一级」（这一条今天靠
    `_core_candidates` 的顺序保证，重写提示词时极易破坏）
  · `research()` 不传新输入时仍退回行业级预研 —— 两标量降级路径要走它
- 语料库入库改动的三项：
  · 公告标题分类器：实质类与程序类各给一组真实标题，断言分类结果；
    **并钉住它不调模型**（传一个会 raise 的假 client，仍须跑通）
  · 三个定性模块的提示词上限：构造 20 篇 COMPANY 文档，断言进提示词的只有
    8 篇、而 `corpus.docs` 仍是 20 篇 —— 上限在提示词层不在入库层
  · `gaps._match_announce` 的召回：同一个因子，在 8 篇池子里搜不到、在 20 篇
    池子里搜到 —— 这是放宽条数的全部收益所在，必须有测试钉住

- 第二次调用试跑后的修订（均不调模型）：
  · 检索词字面前缀被剥掉；格式行占位符不会再被当成前缀（钉住提示词里没有
    裸的 `:检索词` 写法）
  · 联网结论解析：结论引多篇文章、文章晚于 as_of 被剔除、全部被剔除时结论丢弃
  · 数字出处标注：真实实验样本（`tests/fixtures/` 存本次 5 条原样输出与对应
    原页正文）上，「7628」标 ⚠、「第5轮」↔「第五轮」标 ✓、全角数字标 ✓
  · 反爬挑战页（存捷配那一页）标「无法打开」，**不**标成「结论未能核实」
  · `--assume` 读回 `factors.json` 后文章回到语料库；人改过结论后数字标注按
    改后文字重算
  · 门② 快照缺口按审计实际结果逐条列出，含 em_rates；门① 按实际 `store.load`
  · 主题覆盖：声明覆盖 / 声明未覆盖 / 未交代退回词面三档；声明读回不丢
  · 数据线索里的账本 key 精确匹配（`industry.revenue` 不误中
    `industry.revenue_yoy`）；as_of 之后披露的不算

## 不做（YAGNI）

- 不做 `--skip-stance`（用户明确否决）
- 不把平衡三元组直接当判断项（会绕过 `assume` 既有的三档拉开/依据可核验/锚定覆盖
  全套校验，那些校验是按「AI 填」设计的）
- 不改第二阶段任何环节
- 不修「em_macro / eastmoney_report 缺快照」这个结构性缺口 —— 本次只是把它从
  每轮告警改为门①的一条已知限制
- 不把公告入库搬进 `_analyse_facts`（确定性层）—— 挑选确定性化之后原本禁止它的
  理由已消失，但搬进去会让第二阶段每轮重抓 PDF，收益只是省掉一套正在正常工作的
  落盘读回机制。独立清理，不混进这次重构。详见「语料库入库」一节
