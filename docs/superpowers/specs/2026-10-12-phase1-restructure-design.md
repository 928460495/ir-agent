# 第一阶段流程重构设计

## 目标

把第一阶段从「一次调用跑完、只在结尾有一道人工门」改为**四次调用、三道人工门**，
并把多空辩论从「批判已成稿的正文」改为「两个子 agent 采集对立证据、辩出一个带数值
区间的平衡点」。

第二阶段（`--value`：建模 → 完整研报 → 辩论 → 回写）**不变**。

## 为什么改

现状的两个问题，都是实跑暴露的：

1. **人只在最后一道门介入，而那时资料与结论都已固定。** 实测（生益科技 2026-10-06）：
   批准清单第 37 行那张合成表显示五年营收 8.05 倍、隐含份额 39.2%，批准人签了名，
   我也没看。资料来源从未经人核验 —— 而其中「em_macro / eastmoney_report 缺原始接口
   快照」这条告警已经连续六轮出现，始终只在终端一闪而过。

2. **辩论批判的是成稿，而不是证据。** 它能抓住「这句话站不住」，抓不住「这批证据
   被单向挑选过」。多空双方各自采证，才可能暴露证据选择本身的偏向。

## 新流程

```
① --analyse out/X
   取数与事实账本 → 定量采集 → 语料库入库 → 定性分析
   产物: sources.md / sources.json / openweb.json / announce.json / pdf/ / state.json
   【门①：来源核验】verified_by

② --brief out/X --verified-by <名字>
   多空辩论① → 方法论预研 → 因子定向采集 → 多空辩论② → 撰写简报
   产物: stance_a.{md,json} / drivers.md / stance_b.{md,json} / brief.md / review.md
   【门②：结论核验】reviewed_by

③ --assume out/X --reviewed-by <名字>
   AI 填判断项 → 算术后果 → 结构审查 → 假设辩论
   产物: assumptions.{md,json}
   【门③：判断项核实】approved_by

④ --value out/X --approved-by <名字>
   建模 → 完整研报 → 辩论 → 回写（不变）
```

每家公司 **4 次命令、3 个签名**。

已知代价：这个项目记着一条教训 ——「门加多了人会开始机械点同意」
（`test_分解式立刻落盘且说明可覆盖`）。三道门的风险是人在每道门上都只扫一眼。
对策只有一个且不在代码里：三道门审的东西互不重叠（来源 / 结论 / 数值），
谁也替不了谁。

## 阶段间交接：复用现成机制，不新建

每次调用的开头都是「重建确定性层（不花模型钱）→ 读回上一阶段的模型产物 → 继续」。
这正是 `--value` 已经在做的事。

| 要跨调用传递的 | 办法 |
|---|---|
| 事实账本 | 每次调用 `run()` 重建 |
| 派生事实（industry./macro./comps.） | `_analyse_facts` 重建，不调模型 |
| 定性分析结果 | `state.json` 的 `md` / `pr`（已在存） |
| 外部语料与公告 | `openweb.json` / `announce.json` + `_restore_announce`（已能读回） |
| 年报 PDF | `pdf/` 缓存（已有） |
| 多空辩论产物 | `stance_a.json` / `stance_b.json` —— **新增**。`stance_b.json` 必须从第②次调用传到第③次，判断项要用那组三元组做候选输入 |
| 分解式 | `drivers.md`（已有往返格式，人可编辑后读回） |
| 签名 | 与 `--approved-by` 同一套：参数缺失即拒绝运行 |

**第②次调用的五个模型环节逐个立刻落盘**（`stance_a.md` → `drivers.md` →
`stance_b.md` → `brief.md`）。它串了五个模型环节，而今天的实测里这五个各自都失败过；
没有中间落盘点的话，失败会丢掉已完成的部分。

## 多空辩论（新模块 `ir_agent/stance.py`）

`debate.py` 不动 —— 第二阶段的成稿辩论仍在用它。

### 三个 agent，一轮三次调用

```
多方 agent：从给定证据里挑出支持更高估值的，逐条给依据
空方 agent：从同一批证据里挑出不利的，逐条给依据
裁决 agent：对质两侧材料，给出平衡点
```

双方拿到**同一份**证据（事实清单 + 语料库 + 定性结论），任务相反。

### 两轮的产物形态不同

| | 辩论①（预研之前） | 辩论②（因子采集之后） |
|---|---|---|
| 可用输入 | 定量事实 / 语料库 / 定性结论 | 以上 + 因子采集结果 |
| 产物粒度 | 按驱动主题（需求/价格/成本/份额/政策） | 按因子 |
| 产物形态 | 文字平衡结论 | `(空方值, 平衡值, 多方值)` 三元组 + 各自依据 |
| 下游 | 预研设计分解式的框架输入 | 判断项三档的候选输入 |
| 落盘 | `stance_a.{md,json}` | `stance_b.{md,json}` |

### 约束：能用代码查的和只能靠判断的分开

| 约束 | 谁来查 | 阻断？ |
|---|---|---|
| 两侧每条证据的依据（FACT 占位符 / REPORT 引文 / EXTERNAL URL+引文+日期） | 代码 `basis.validate` | **不阻断**，核验不过的逐条标注 |
| 平衡值落在两侧之间：`空方值 ≤ 平衡值 ≤ 多方值` | 代码 | **阻断**，驳回重试 |
| 判断项偏离平衡三元组时，该行必须填 `deviation` | 代码查**存在性** | **阻断** |
| 偏离的理由站不站得住 | 结构审查（第 3 道） | 不阻断，标注 |

**为什么证据核验不阻断**：实测三场辩论被契约杀掉（占位符缺失、裸数字、
「分位数之后多写一个单位」），每次损失一整场。而「核验 + 标注、不阻断」是这个项目
已经在用的模式 —— 判断项那边早就这么做：「N 行依据未能逐字核验（已标注，未阻断，
需人工复核）」。它不降低成功率，又保留检出能力：核验不过的那几条当场标出来，
人在门②一眼能看到。

**为什么平衡值要阻断**：裁决者不能自己造数，它只能在两侧划出的区间里选。
这是这套设计里唯一能确定性保证的东西 —— 平衡点对两侧可问责。

**`deviation` 的作用**：让「无视辩论」和「有理由地偏离」在产物上长得不一样。
没有它的话，判断项中性档 18%（平衡点 12%）这件事，无论是模型看到了因子细节
而上调、还是模型压根没读辩论，产物上完全一样。同构的实测案例：判断项被锚定覆盖
（批准 19.12% → 实际用 −1.58%）之所以能被人看见，唯一原因是代码专门为它生成了一行
说明。

## 失败处置：没有降级，只有重跑或人工补写

**取消全部自动降级。** 任何多空环节失败时流程停止，终端给出两条可粘贴的命令：

```
多空辩论① 未完成：裁决者三次给不出落在两侧区间内的平衡值
最后一稿已落盘：out/X/stance_a_failed_raw.md
已生成待填模板：out/X/stance_a.template.json

  ① 原样重试（模型重抽）
     python -m ir_agent 600183 --year 2025 --brief out/X --verified-by <名字>

  ② 人工补写：按模板填好 out/X/stance_a.json，然后
     python -m ir_agent 600183 --year 2025 --brief out/X --verified-by <名字> --accept-manual
```

`--accept-manual` 读回人填的 JSON，跳过该环节的模型调用，并在产物中记录
「本轮多空输入由 <名字> 人工补写」。

**不存在「跳过」这条路。** 每份研报的多空输入要么来自模型、要么来自人，不会「没有」。
已知代价：某家公司反复失败时流程会卡住，直到有人手写那份 JSON。

## 两道新人工门的产物

### 门① `sources.md` + `sources.json`

| 资料类别 | 清单给出 |
|---|---|
| 账本事实 | source_id、接口名、原始响应快照的位置（有/无） |
| 外部文档 | URL、本地缓存路径、抓取日期、来源分级、主机校验是否降级 |
| 公司公告 | 标题、披露日、巨潮 URL、`pdf/` 本地路径 |
| 年报 PDF | 本地路径、页数、是否被 `PDF_MAX_PAGES=30` 截断 |
| 行业/可比 | 同业样本名单（牧原 11 家 vs 生益 46 家，代表性差异要让人看到） |

**已知缺口在这道门显式列出**，不再每轮在终端重复：

```
⚠ 以下来源不具备完整可溯源性（结构性限制，非本轮故障）：
   em_macro / eastmoney_report —— 数字从文本抽出，未保留原始接口响应
   本轮涉及 18 条引用
```

**代码在这道门查**：清单里列出的每个本地文件路径逐个 `stat` 确认真的在磁盘上。
防的是「清单引用了一个从未保存的文件」。内容由人负责。

### 门② `brief.md` + `review.md`

`review.md` 是一张待核清单，把所有「代码没把握」的东西聚到一处：

```
多空证据中代码核验不过的：N 条（逐条列出）
简报引用缺原始接口快照的：N 条（来源）
```

### 三个签名进最终研报附录

```
资料来源经 <verified_by> 核验（日期）
简报结论经 <reviewed_by> 审阅（日期）
DCF 判断项经 <approved_by> 核实（日期）
```

解决的是一个对外的问题：半年后有人读这份研报，他怎么知道哪些部分有人看过。
今天的附录只有一行「判断项经 xhl 核实」，而 xhl 核实的只是 40 行三档数值 ——
资料来源没人核过、简报结论没人审过，读者无从分辨。

## 要改的既有不变量

1. **删掉 `test_预研排在数据采集之前`**。该测试的理由是「先问这个行业靠什么赚钱，
   再按答案去采集数据 —— 顺序反了就退化成『先收集再解释』」。新顺序接受这个代价，
   换取「分解式能基于全部证据与多空结论设计」。
   **必须换上一条新的**：预研仍须排在因子采集之前，否则「按分解式定向采集」无从谈起。

2. **第一阶段的 `_write_and_debate` 拆开**：撰写留在第②次调用，旧的成稿辩论删除。
   `_debate_and_revise` 不动（第二阶段仍用）。
   **已知损失**：简报从此没有任何自动化环节读它。今天实测里旧辩论抓到的都是成稿层面
   的错（HHI 因果方向倒置、「衰退阶段」无据、「16.5 家」伪精度、「52 亿在建项目」
   无依据）。这几类今后只能靠门②发现。

3. **`next_actions` 要认识四个状态**，按产物推断当前停在哪道门，并给出可粘贴的下一条
   命令。它的 docstring 写着「过时的指引是会主动误导人的那种错」。

## 测试策略

- `stance.py` 的纯函数全部单元测试：两侧证据解析、平衡值区间校验（含变异）、
  模板生成、`--accept-manual` 读回
- 阶段切分用**行为测试**而非源码字符串匹配：打掉模型调用，断言每次调用的产物集合
  与停止点。本会话已有四次「结构式断言盯着源码字面量」而误报/漏报的记录
- 门①的文件存在性校验：建临时目录，列一个不存在的路径，断言报错
- `deviation` 存在性校验的变异验证：摘掉检查后对应测试必须变红

## 不做（YAGNI）

- 不做 `--skip-stance`（用户明确否决）
- 不把平衡三元组直接当判断项（会绕过 `assume` 既有的三档拉开/依据可核验/锚定覆盖
  全套校验，那些校验是按「AI 填」设计的）
- 不改第二阶段任何环节
- 不修「em_macro / eastmoney_report 缺快照」这个结构性缺口 —— 本次只是把它从
  每轮告警改为门①的一条已知限制
