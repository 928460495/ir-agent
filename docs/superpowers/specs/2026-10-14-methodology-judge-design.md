   **待采集**（逻辑正确，资料尚未采集到）。有一项致命即驳回；提醒、待采集不驳回，
   写进 drivers.md 并列入门② 待核清单。

本次（2026-10-14）：

5. 清单 **7 类全要**：模式、因子、正交、公式、常量、账本、覆盖。
6. 审核者看**提出者看到的全部 + 代码额外算出的事实**；**不联网**（资料不够由
   「待采集」承接）。
7. 门③ 的因子结构审查**只保留 [对账]**；[因子]、[正交] 删掉（预研阶段已审）。
   预研审核的提醒、待采集带进门③ 清单。
8. **人改过的 drivers.md 不再送审，只标注**「人工修改后未经审核」—— 按分解式

## 一、流程与轮次

一轮：

1. **提出者**写分解式（现有预研提示词、联网 client）。
2. **代码查能不能算**。不过 → 原因交回提出者重写，**算一轮**。代码只保留会让
   计算或存储做不下去的检查：公式能否解析、名字是否声明且合法、模式是否合法、两条
   公式是否都有、因子 key 是否撞车（采集结果与工作簿按 key 对行）。子项目一过渡期
   保留的三道**移交审核者**（决定 1）：
   - 每条公式 2–5 个因子 → [公式] 条目判「因子个数是否合适」；
   - 声明了的因子必须进公式 → [因子] 条目判「是否进了公式」；
   - 检索词至少 2 个字 → [因子] 条目判「检索词是否过短或过泛」。代码不再因检索词
     长度驳回（`Factor` 构造时的长度检查改为只在旧 `分解:` 写法读回时保留）。
3. **代码生成清单**（二），并算出只给审核者的额外事实。
4. **审核者**逐项作答。漏答 → 退回补答，最多 2 次，**不消耗提出者轮数**；仍不全
   → 「审核未完成」，**不当通过**。
5. **代码按规则汇总**：有致命 → 驳回，全部致命项（含理由）与提醒项交回提出者，
   算一轮；无致命 → 通过。

步骤 2、5 的驳回都计入轮数，**合计最多 3 轮**。

- **通过** → 写 drivers.md，进入因子采集、辩论②。
- **3 轮未过 / 审核未完成 / 模型接口失败** → **停下交人工**。终端给两条可粘贴做法：
  - 重跑 `--brief`（没有 drivers.md，会重新预研）；
  - 以落盘的最后一稿为底，人工改好存为 drivers.md，再重跑 `--brief`（读回时认作
    「人工修改后未经审核」）。
  - 接口失败的措辞要写明是接口问题、重跑即可。
- **每一轮都落盘** `drivers_rounds.md`：提出者原文、代码检查结果、审核者逐项结论。
  此前只存最后一稿，前两次为什么被驳回无从查证。
- 两个 client：提出者联网；审核者不联网。

## 二、清单、作答格式与审核者的资料

**清单由代码生成**：

| 类别 | 条目 | 审核者判什么 |
|---|---|---|
| [模式] | `模式` | 变化/水平是否与行业特性、可得资料相符 |
| [因子] | 每个因子 `<短名>（<完整名>）` | 有无公开口径、单位对不对、分母在公司内外、现有资料能否支撑、是否进了公式、检索词是否过短或过泛（附命中次数） |
| [正交] | 同一公式内每两个因子 `<A> × <B>`（共用因子对只列一次） | 是否同一个量被重复计算 |
| [公式] | `营收`、`毛利率` | 量纲是否自洽（换算写对没有）、能否算回营收/毛利率、累计还是逐年与因子填法是否一致、因子个数是否合适（一个不叫分解，超过五个人核实不过来） |
| [常量] | 每个常量 `<名字>` | 数值与出处是否对得上 |
| [账本] | 每个 `[[key]]` 声明 `<短名>：<key>` | 账本 key 与因子是不是同一个量、口径是否一致 |
| [覆盖] | 每个辩论主题 `<主题>`（辩论① 无结论时不列） | 有无因子承载；声明未覆盖的理由是否成立 |

**作答格式**（沿用 `factor_review`，结论与理由间全角空格）：

```
[因子] 份额增速（本司市占率同比增速）：提醒　分母是全行业规模，逻辑成立；但口径需与 [[company.market_share@2025FY]] 对齐
```

- 四级定义原样写进提示词。
- 提醒、致命、待采集**必须写理由**，没写算漏答。
- 涉及资料的判断引原文「…」或账本占位符；代码核对能否在语料、年报、账本里找到，
  找不到的**只标注**「引文核验不过」，不改结论（与多空辩论一致）。

**审核者的资料**：

- 与提出者相同：账本事实摘要、账本 key 清单、语料库（研报与公告）、年报叙述章节、
  定性结论、辩论① 平衡点、提出者的分解式原文。
- 只给审核者（代码现算）：
  1. 每个 `[[key]]` 声明在账本里实际取到的值与期间，没取到的标明；
  2. 每个因子检索词在语料里的实际命中次数；
  3. 主题覆盖的字面匹配结果、覆盖声明的核对结果；
  4. **水平模式试算**：账本拿得到的基期值代入公式，算出第 0 年营收与毛利率，与报表
     实际值并排；基期值不全则写明「缺 X 的基期值，无法试算」。

## 三、落盘与门②、门③

- **`drivers_review.json`**：最后一轮逐项结论（类别、条目、结论、理由、引文核验）、
  轮数、审核时分解式定义的**指纹**（定义文本的哈希）。
- **drivers.md** 新增「方法论审核」一节：第几轮通过；提醒、待采集逐条列出；通过只给
  条数。
- **重跑读回**：drivers.md 定义的指纹与 `drivers_review.json` 一致 → 沿用结论，不调用
  审核者；不一致或没有 `drivers_review.json` → 标注**「人工修改后未经审核」**（drivers.md
  顶部、终端清单、门② 待核清单），**不送审**。
- **门② review.md** 新增「方法论审核」一节：提醒与待采集条目；人工修改过的写明未经审核。
- **门③**：
  - `factor_review` 只保留 **[对账]**（只标注、不阻断，不变）；两标量模式本就只有
    [对账]，不受影响。
  - assumptions.md 顶部新增**「方法论审核遗留」**：从 `drivers_review.json` 读出的提醒、
    待采集条目。第三次调用不重新审核。
- **终端措辞**：「方法论审核 3 轮未通过（最后一轮致命 N 条）」与「人工修改后未经审核」
  都要登记进 `research._PREFIX`（否则默认渲染成「未生成」）。

## 四、异常、测试与边界

| 情况 | 处理 |
|---|---|
| 3 轮都有致命项 | 停下交人工 |
| 审核者补答 2 次仍不全 | 「审核未完成」，停下 |
| 提出者或审核者接口失败 | 停下，写明接口问题，重跑 `--brief` 即可 |
| 取不到申万行业分类 | **保持现状**：退回两标量并 ⚠ 标注（不是审核没通过，决定 2 不管这里） |

- 停下时辩论① 已落盘，重跑沿用；因子采集、辩论②、简报都不执行；终端「下一步」给
  两条做法。
- 判断项环节自身的「因子模式失败 3 次退回两标量」（I4）不在范围内，不变。

**测试**（脚本化的假提出者、假审核者，不调模型）：

- 清单生成：7 类齐全；共用因子对不重复；无辩论① 结论时没有 [覆盖]。
- 作答解析：四级结论；提醒/致命/待采集无理由算漏答；漏答逐条列出。
- 汇总与轮次：有致命即驳回；代码检查不过算一轮；补答不消耗轮数；第 3 轮仍不过停下。
- 落盘：每轮写 `drivers_rounds.md`；指纹不变沿用、不调用审核者；指纹变了标未经审核、
  不调用审核者。
- 额外事实：账本值、命中次数、水平模式试算（含基期不全）。
- 门② 与门③：review.md 一节；assumptions.md「方法论审核遗留」；`factor_review` 只剩 [对账]。
- 终端：新措辞登记进渲染（现有穷举守卫逼着登记）。
- 端到端：第一轮驳回、第二轮通过，一路到简报；3 轮不过时停在预研、不往下走。
- 关键规则做变异验证。

**不做**：审核者联网；人改过的分解式送审；改判断项环节的 I4 降级；改多空辩论。

## 修订（2026-10-14，生益科技第二次调用试跑后）

试跑一（`ab831d5` 之前）：三轮都卡在代码检查 —— 提示词的格式行写成单行反引号，
提出者照抄，`lineparse.keyed` 不认行首反引号，报的却是「缺少两条」。已修：行首
反引号也认、格式行改放代码块、认不出时直说（`ab831d5`）。

试跑二：审核者第一次上岗。第 1 轮判出「产销量增速 × 份额增量」重复计算（份额
增量 = 本司营收增速 − 行业增速，已含产销量贡献）；第 2 轮把「两个因子共用一条
证据」判为致命；第 3 轮审核未完成（漏 [公式] 两条、[账本] 两条），审核者原文
未落盘，原因无从确认。用户决定：

9. **审核者原文落盘**：每次作答（含被退回补答的）原文与不完整原因都写进
   `drivers_rounds.md`。围栏长度随原文里最长的反引号串加长。
10. **条目名容错**：[账本] 条目照提出者原文列（保留 `@期间`）；比对时 `[[key]]`
    带不带 `@期间` 都认；[公式] 条目名后面抄了「= …」也认。理由里的占位符不动。
11. **[正交] 口径**：只看量是否重复；两个不同的量共用同一条证据来源是资料问题，
    判提醒或待采集，不判致命。
12. **审核者给修改建议**：每条可写「建议：…」，与理由分开存（`Verdict.suggest`，
    进 `drivers_review.json`）。**致命必须写建议**，没写算不完整（退回补答，不
    消耗提出者轮数）；提醒、待采集可选。驳回时建议随致命项一并交回提出者。
