# 驱动因子分解：先问「这个行业靠什么赚钱」，再去采集数据

日期：2026-09-12

## 问题

当前框架的形状是**固定模板 + 填数据**。`industry_profile.py` 算的三样东西 ——
集中度（HHI/CR5）、生命周期、周期敏感度（DOL/DFL/DTL/收入弹性）—— 全部只需要
利润表和资产负债表。它们之所以"通用"，是因为它们回避了行业特性：任何行业都能
算 HHI，但 HHI 不告诉你封测的毛利率由什么决定。

于是 AI 填判断项时，手上只有历史增速统计、行业增速、份额变化、五力的定性判断。
这是一个制造业公司的**纯报表视角**。

对封测而言，真正的驱动链是：

    营收   = 产能 × 稼动率 × 单价
    毛利率 ← 稼动率（固定成本摊薄）+ 折旧节奏（扩产周期的滞后冲击）
            + 上游基板/金线/晶圆价格
    供需   ← 全行业扩产计划 vs 下游需求

这四行里当前框架一个变量都没有。所以报告能说「份额在丢所以增速取低于行业」，
但说不出「新增产能爬坡使折旧前置、稼动率不足时毛利率先降后升」—— 而后者才是
封测毛利率的实际形状。

**缺的不是几个指标，是缺一个环节去问「这个行业靠什么赚钱」。** 这个问题从来
没被问过，答案被硬编码成了五力 + 杜邦。

## 目标

在数据采集之前插入方法论预研，由它产出**算术闭合的驱动因子分解式**；按分解式
识别数据缺口并定向采集；判断项改为逐因子填写，由代码合成回营收增速与毛利率。

核心不在于让 AI 想得更多，在于**让人能检查 AI 想得够不够** —— 清单上如果没有
「稼动率」这一行，人一眼就知道这个因素没被纳入。

## 流程

    阶段一  --analyse
      ⓪ 方法论预研（新）  WebSearch：该行业怎么估值、营收与毛利率由什么驱动
                          → drivers.md 立刻落盘（可中断、可改、可重跑）
      ① 数据层（现有）    东财 × 新浪双源 → 账本
      ② 缺口识别（新）    对照分解式，哪些因子账本里没有
      ③ 定向采集（新）    年报 → 公告 → 研报语料库 → 开放网络
      ④ 分析层（现有）    宏观/周期/行业/可比/战略/产业链
      ⑤ 简报 → 辩论 → 回写（现有）
      ⑥ 判断项（改造）    按分解式逐因子填 → 代码合成
                          → assumptions.md【人工核实】
    阶段二  --value
      建模（含 1b_驱动分解 工作表）→ 完整研报

预研产出不单独设人工门。**门的价值会被数量稀释** —— 现有那道判断项的门之所以
有效，是因为它一次只要求人看一件事；再加一道，人看两次的注意力未必比看一次多。
改用「立刻落盘 + 可中断 + 可覆盖」换取早期干预，不消耗那份注意力预算。

## 分解式：表示与校验

```python
class Op(Enum):
    MULTIPLY = "乘"      # 营收增速 = Π(1 + 因子变化率) − 1
    ADD_PP   = "加"      # 毛利率   = 基期 + Σ 因子贡献(pp)

@dataclass
class Factor:
    key: str          # capacity | utilization | asp
    label: str        # 产能 / 稼动率 / 单价
    unit: str         # "变化率" 或 "pp" —— 必须在白名单里
    source_hint: str  # 这个数去哪找
```

### 闭合校验（硬拦截）

| 规则 | 理由 |
| --- | --- |
| 营收只能用 MULTIPLY，因子单位一律「变化率」 | 乘法链才能还原增速 |
| 毛利率只能用 ADD_PP，因子单位一律 pp | 毛利率是比率，变化只能加减 |
| 因子数 2–5 | 一个不叫分解；超过五个人核实不过来 |
| 单位必须在白名单 | 挡掉「客户结构优化」这类无法量化的因子 |

最后一条是真正的闸门。AI 很容易产出听着专业但不闭合的分解 ——
「产能 × 稼动率 × 单价 × 客户结构优化」前三项能乘、第四项不能。要求每个因子
必须声明单位，写不出单位的项就写不进来。

### 历史回算：报残差，不判对错

**Π(1+r_i) 几乎永远不会精确等于实际营收增速** —— 产品结构、汇率、并表范围都会
留下残差。若要求严格相等，没有一个分解式能通过。

因此回算的产出是**残差序列**而非通过/不通过：

    2023  分解 −3.8%  实际 −4.2%   残差 −0.4pp
    2024  分解 +17.1% 实际 +18.5%  残差 +1.4pp
    2025  分解 +12.9% 实际 +14.1%  残差 +1.2pp

残差小且稳定 → 分解抓住了主要矛盾。
残差大或跳动 → 有重要因子没被纳入，必须写进批准清单让人看见。
因子历史值取不到 → 标「无历史校验」，绝不静默跳过。

**不设硬上限**：代码判断不了多大算大，不同行业差异极大。残差只显示，由人判断。

## 定向采集与来源分级

采集顺序，先近后远、先可核验后不可核验：

1. 账本 —— 已有事实（在建工程、固定资产等产能的间接代理）
2. 年报叙述章节 —— 产能/产量/在建项目的文字披露 → EXTRACTED 入账本，confidence<1
3. 巨潮公告 —— 同业扩产项目（投产时间、设计产能）
4. 研报语料库 —— 已抓的深度报告里常有全行业产能测算
5. 开放网络 —— WebSearch 定向找 SEMI 出货、基板报价、协会产能统计

### 来源分级的新约束

复用 `sources/external.py` 现有三级（OFFICIAL / SELLSIDE / MEDIA），新增：

> **MEDIA 级不得单独支撑一个因子的取值。** 必须有 OFFICIAL 或 SELLSIDE 佐证，
> 否则该因子标注「仅单一媒体来源」并在批准清单上高亮。

现有分级管的是「能不能引用」；因子取值是**要进模型算钱**的，门槛要更高。一条
财经媒体报道可以作为线索，不该单独决定 DCF 里的产能增速。

**一条必须写进代码注释的边界**：外部引文只能核验「我确实在某个网址上抓到过
这句话」，核验不了「这句话是对的」。账本数字可以一路反查到接口原始响应，外部
数据不能。两者在报告里长得一样，但证明力差一个量级 —— 分级不是给来源打分，
是限定它能支撑多强的结论。

### 采集不到怎么办

封测稼动率 A 股基本不披露，大概率会出现「分解式说要稼动率，但哪儿都找不到」：

- 该因子在批准清单上标「无数据，取值为估计」
- 取值必须由人给，或 AI 给但明确标注为无依据估计
- **绝不用代理指标偷偷顶替**（如拿固定资产周转率冒充稼动率）—— 那会让一个估计
  伪装成测量

## 判断项与批准清单

`assume.py` 从「填两个标量路径」变为「按分解式逐因子填」。校验规则逐因子生效：
三档严格拉开、每年都要给、每条都要有可核验依据 —— 规则不变，只是从作用在 2 项
上变成作用在 N 项上。

批准清单形状：

    本次采用的分解式
      营收   = 产能 × 稼动率 × 单价
      毛利率 = 基期 + 稼动率摊薄 + 折旧变动 + 上游成本
      历史回算残差：−0.4pp / +1.4pp / +1.2pp（小且稳定）

    ## 营收 — 2026E
    | 因子 | 悲观 | 中性 | 乐观 | 理由 | 依据 | 数据 |
    | 产能   | +8%  | +12% | +15% | 长电新厂 Q2 投产… | 年报「…」 | 已披露 |
    | 稼动率 | −8pp | −3pp | +2pp | 全行业扩产叠加…   | SEMI「…」 | ⚠ 无数据，估计 |
    | 单价   | −5%  | −2%  | +1%  | 竞争加剧压价…     | 研报「…」 | 已披露 |
                  ↓ 合成营收增速  −5.4% / +6.4% / +18.4%

## 工作簿改动

新增工作表 `1b_驱动分解`：因子 × 年 × 三档，用 **Excel 公式**合成营收增速与
毛利率；`1_假设` 的对应单元格**引用**它。改一个稼动率 → 营收 → 利润 → FCFF →
每股价值整条链自动重算。

### 必须配套改 ashare_verify

`read_inputs` 目前读三档取值是 `float(a.cell(r, 1+scen).value)` —— 直接取值不
解析公式；`g()` 的引用正则 `=\$?([A-Z]+)\$?(\d+)` 只认本表引用。跨表引用会让它
拿到公式字符串然后 `float()` 抛异常，**独立复算验证会断掉**。

改动范围明确：正则扩展到跨表；`path3` 复用同一套解析。改完用现有 140 格独立
复算立刻验证。

## 失败与降级

| 情形 | 处理 |
| --- | --- |
| 方法论预研搜不到东西 | 退回不分解（现有两标量模式），清单标明原因 |
| 分解式连续 3 次不闭合 | 同上，退回不分解 |
| 某因子采集不到 | 标「无数据，取值为估计」，不用代理指标顶替 |
| 历史回算残差大 | 不阻断，清单上高亮 |
| 跨表引用改动导致验算失败 | **硬失败** —— 验证核心不容降级 |

前四种是「降级但继续」，损失的是精度；最后一种损失的是**担保本身**，不能降级。

## 不做的事

- 不建「行业 → 分解式」的人工维护表。维护那张表就是在手工做本该自动化的事，
  与「通用 A 股 agent」的目标相悖。
- 不给分解式单独设人工批准门（理由见「流程」）。
- 不在残差上设硬上限。
- 不改 ashare-dcf 的建模逻辑，只加一张表并扩展它的读取器。
