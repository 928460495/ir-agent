# 判断项环节：填写者 + 审核者（子项目三）

> 2026-10-15。子项目一（分解式公式化）、子项目二（方法论预研改为提出者 + 审核者，
> `2026-10-14-methodology-judge-design.md`）已落 main。本文把同一套做法延伸到
> 第一阶段之三 `--assume`：判断项的合格与否**全部由 AI 判定，代码不做任何驳回**。

## 背景

生益科技（600183，2025）第三次调用（2026-10-15）：第二次调用已经给出完整的公式化
分解式（4 个因子、2 条公式，方法论审核第 3 轮通过），第三次调用却「因子模式连续
3 次填不出合格的判断项」，退回两标量模式，因子分解整个丢失。三次被拒的判定者全部
是代码（`assume._parse_factors` / `assume.check`，共 49 处 `AssumeFailed`）：

| 次 | 判定标准 | 实际 |
|---|---|---|
| 1 | 中性档偏离辩论② 平衡点超过 0.01 且无偏离说明 | 平衡点本身单位错（pp 因子写成小数 0.035），模型按 pp 填被判偏离 |
| 2 | 合成后毛利率三档单调 | 两个 pp 因子各自拉开，加总后第 4 年倒序 |
| 3 | 第 6 段必须是可核验的依据 | 模型写了 7 段（理由在第 6 段、`[[industry.revenue_yoy@2025FY]]` 在第 7 段）——因为第 1 次的驳回信息让它「在该行的第 7 字段填偏离说明」，而解析器只读 6 段。内容是对的 |

三次都与分解式内容无关。门③ 的两个 AI 审核（`factor_review` [对账]、假设辩论）
只在代码全部放行之后才运行，且只标注不阻断。

此前一轮（同日）还出现过：毛利率两个 pp 因子按小数填（理由栏「5.47 个百分点」、
表里 0.0547），公式 `/100` 再除一次，影响缩小 100 倍；代码单位守卫只拦「pp 带 %」，
拦不住；[对账] 判出了矛盾，但不阻断。

## 用户决定（2026-10-15）

1. **完全交由 AI 判定，代码不参与判定。** 代码只读数、计算、核对引文，把结果作为
   事实交给审核者；读不出、算不下去也只作为事实报告。
2. 判定标准为清单 **5 类**：[取值]、[平衡点]、[依据]、[合成]、[后果]（由 7 类草案
   合并：[读数] 并入 [取值]，[理由] 并入 [依据]）。
3. **假设辩论并入审核者**，不再单独跑；审核者作答可附选填的「补充」，承接清单之外
   的问题。
4. 审核者的资料：填写者看到的全部 + 代码事实 + **完整账本事实目录**（原假设辩论用的
   `FactCatalog`），**不联网**。
5. 第二阶段读回人改过的判断项：**不送审，只标注**「人工修改后未经审核」并列出改动
   （与子项目二决定 8 同一套指纹机制）。
6. 辩论② 的提示词**不改**：平衡点的小数/单位错误由审核者判出，在建议里告诉填写者，
   **由填写者换算**。
7. 沿用子项目二：四级结论（通过 / 提醒 / 致命 / 待采集，定义原话见子项目二 spec）、
   致命必附修改建议、最多 3 轮、仍不通过停下交人工、**不再退回两标量模式**。

## 一、流程与轮次

一轮：

1. **填写者**填判断项（沿用现有判断项提示词；其中「代码会拒绝……」类闸门说明改写
   为填写规则）。
2. **代码读数与计算，不驳回。** 把每格文本读成数，按公式算合成路径与隐含份额，核对
   引文；全部作为「事实」交给审核者。读不出的格子、算不下去的地方同样作为事实报告。
3. **审核者**按清单逐条作答，可附「补充」。漏答 → 退回补答，最多 2 次，**不消耗填写
   者轮数**；仍不全 → 停下。
4. **汇总**：有一条致命 → 全部致命项（含理由与建议）与提醒项交回填写者重填，算一轮；
   无致命 → 通过。

- **最多 3 轮。** 3 轮仍有致命 / 审核者答不全 / 模型接口失败 → **停下交人工**。终端给
  两条做法：原样重跑 `--assume`；或以最后一稿为底人工改好 `assumptions.json` 再跑
  `--value`（读回时标「人工修改后未经审核」）。
- **不再退回两标量模式。** 两标量只在「取不到申万行业分类」时出现（方法论环节的既有
  降级），此时审核照跑。
- **每一轮都落盘** `assumptions_rounds.md`：填写者原文、代码事实摘要、审核者每次作答
  （含被退回补答的）原文与逐条结论。
- **唯一由代码报告的停止**：审核者判通过，但代码确实算不下去（如某格是「约两成」而
  审核者没判致命）→ 停下并写明「审核已通过，但无法计算：<哪一格、为什么>」。这不是
  代码判对错，只是如实说明做不到。

## 二、清单、作答格式与审核者的资料

**清单由代码生成**：

| 类别 | 条目 | 审核者判什么 |
|---|---|---|
| [取值] | 每个因子 `<短名>（<完整名>）` | 代码读到的值是否就是填写者的本意、单位是否与声明一致（pp 是百分点数字本身，变化率是百分比）；三档方向与间距（侵蚀类因子悲观更负）；逐年路径；累计还是逐年与公式 `基期(·)` / `上期(·)` 是否一致 |
| [平衡点] | 有辩论② 平衡点的因子各一条 | 中性档与平衡点的关系、偏离理由是否成立；**平衡点本身的单位是否可信** —— 不可信时在建议里写出换算后的值，由填写者换算 |
| [依据] | 每个因子一条 | 依据能否支撑取值（引文核验结果作为事实）；「无数据（估计）」是否属实、「同上」是否合理；理由与取值是否自洽；是否回应方法论审核遗留的提醒/待采集 |
| [合成] | `营收`、`毛利率` | 合成后三档是否拉开、单调；合成路径与理由栏引用的参照（行业增速、历史 CAGR、同业水平）是否自洽；与半年报锚定的首年是否衔接 |
| [后果] | 一条 | 5 年累计倍数、隐含市占率在行业格局、产能、CR5 下是否可能 |

两标量模式：[依据]（营收增速、毛利率各一条）、[合成]、[后果]。

**作答格式**（沿用子项目二）：

```
[类别] <条目>：<通过|提醒|致命|待采集>　<理由>　建议：<具体怎么改>
补充：<致命|提醒>　<清单之外发现的问题>　建议：<怎么改>
```

- 四级定义原样写进提示词。致命必写建议，没写算漏答；提醒、待采集可选。
- 「补充」选填；补充判致命同样驳回。
- 涉及资料的判断引原文「…」或账本占位符；代码核对，找不到的**只标注**「引文核验
  不过」，不改结论。
- 条目名容错沿用子项目二（`[[key]]` 带不带 `@期间` 都认；[合成] 条目名后抄了「= …」
  也认）。

**审核者的资料**：

- 填写者看到的全部：分析结论、简报、分解式、因子采集结果、辩论② 平衡点、历史统计。
- 代码事实：每格**读到的值与原文并排**、合成后三档路径、隐含份额与累计倍数、每条
  引文的核验结果、方法论审核遗留条目、账本对应 key 的实际取值；读不出、算不下去的
  地方。
- 完整账本事实目录（`FactCatalog`）。
- 不联网。

### 旧闸门 → 新条目对照（删掉闸门，问题仍有人看）

| 旧代码闸门（`assume.py`） | 由哪条承接 |
|---|---|
| 单位字面量（pp 带 %、变化率不带 %、bp） | [取值]：读到的值是否本意、单位是否一致 |
| 三档严格拉开（逐行） | [取值]：三档方向与间距 |
| 合成后单调 | [合成] |
| 依据逐字核验、「缺少可核验的依据」 | [依据]（核验结果作为事实） |
| 「无数据（估计）」只限 MISSING、须有理由；「同上」首行 | [依据] |
| 偏离平衡点须有说明（第 7 段） | [平衡点] |
| 隐含份额阻断 | [后果] |
| `factor_review` [对账] | [合成] |
| 判断项假设辩论 | [后果]、[依据]、「补充」，资料含 `FactCatalog` |
| 字段数、未知因子、年份越界、重复行、缺年份、缺基期 | [取值]（作为读数事实报告）；真算不下去 → 「审核通过但无法计算」停下 |

## 三、落盘、门③ 与第二阶段

- **`assumptions_rounds.md`**：每轮完整记录（见一）。
- **`assumptions_review.json`**：最后一轮逐条结论（类别、条目、结论、理由、建议、
  引文核验）、第几轮通过、判断项取值的**指纹**。指纹只算取值（因子、年、三档），
  不算理由与依据文字。
- **`assumptions.md`**：
  - 顶部新增「判断项审核」一节：第几轮通过；提醒、待采集逐条列（带建议）；通过只给
    条数。
  - 「方法论审核遗留」照旧。
  - 去掉「🔍 因子结构审查」「⚖️ 假设辩论」「🔁 对账退回重填」三节。
  - 因子表每格的 ⚠ 标注（依据未能逐字核验等）照旧——事实，给人看。
  - `_APPROVE_NOTE` 去掉「改完仍会重新校验，改坏了会被挡下来」，改为说明指纹机制。
- **替换掉的旧机制**：`assume.check` 里全部内容闸门；填写环节重试循环与两标量降级；
  `factor_review`；判断项假设辩论；`3c23f30` 的对账矛盾重填（其提示词新增的「pp 填
  5.47 不填 0.0547」保留）。
- **第二阶段 `--value`**：读回后比对指纹。一致 → 沿用结论、不再校验、直接建模；不一致
  → 不送审，研报与终端写明「判断项经人工修改，修改后未经审核」并列出改动的格子（复用
  现有 `edits`）。代码只计算；算不下去（如人把 JSON 改坏）→ 停下写明哪一格。

## 四、异常、测试与边界

| 情况 | 处理 |
|---|---|
| 3 轮仍有致命 | 停下交人工，最后一稿落盘，终端两条做法 |
| 审核者补答 2 次仍不全 | 停下，「判断项审核未完成」，不当通过 |
| 填写者或审核者接口失败 | 停下，写明接口问题，重跑 `--assume` 即可；已有产物不受影响 |
| 审核通过但算不下去 | 停下，写明哪一格、为什么 |
| 取不到申万行业分类（两标量） | 照常审核，清单 3 类 |
| 第二阶段指纹不一致 | 标注「人工修改后未经审核」并列改动，照常建模 |

- 终端措辞「判断项审核 3 轮未通过」「判断项审核未完成」「人工修改后未经审核」登记进
  `research._PREFIX`（穷举守卫测试逼着登记）。

**测试**（脚本化的假填写者、假审核者，不调模型）：

- 清单：5 类齐全；无平衡点的因子不列 [平衡点]；两标量 3 类。
- 作答解析：四级；致命必附建议；补充选填、补充致命驳回；漏答逐条列出；条目名容错。
- 轮次：有致命即驳回；补答不消耗轮数；第 3 轮仍不过停下；不退回两标量。
- **代码只报事实不驳回**：生益科技这次的 3 份失败原文（7 段的行、偏离平衡点、合成
  倒序）都不再被代码拒绝，原拒绝理由出现在审核者的事实里。
- 算不下去：审核通过但有格子读不出数 → 停下并写明。
- 落盘：每轮写 `assumptions_rounds.md`；指纹一致沿用、不一致标注并列改动。
- 门③ 与第二阶段：`assumptions.md` 新一节、三节已去掉；`--value` 不再调内容校验。
- 端到端：第 1 轮驳回、第 2 轮通过，一路到 `--value`；3 轮不过停在 `--assume`。
- 关键规则做变异验证。

**不做**：辩论② 提示词；审核者联网；人改过的判断项送审；方法论预研与辩论①②流程。

**做完后**：用生益科技重跑 `--assume`（`drivers.md`、辩论①② 沿用，门② 签名 xhl），
通过后跑 `--value`（门③ 签名 xhl）。子项目一、二、三合在一起试跑通过后推送 ir-agent。
